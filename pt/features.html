Capabilities

Faça de cada camada
um comportamento verificável

Da seleção da versão de destino e das macros predefinidas aos diagnósticos, ao PCH e aos projetos reais, o CrucibleCpp não se apoia em “deve dar certo”, mas em uma cadeia de testes reproduzível.

A

Versão de destino e perfil

Um pré-processador, três GCC de destino. Escolha a versão e use as macros predefinidas, os dados de __has_* e os caminhos de busca de include.

  • --gcc-version=13|14|15
  • --gcc D:\path\to\g++.exe
  • Detecção automática no PATH, escolhendo por padrão a versão mais alta suportada
  • GCC 13.3 / 14.3 / 15.2 profile
  • C++11 / C++14 / C++17 / C++20
B

Sistema de diagnósticos

Um formato de diagnóstico feito para sistemas de build reais. Inclui a linha do código-fonte, o caret, o include trace e a opção de warning — não apenas uma string de erro.

  • severity / option / caret no estilo GCC
  • -Werror, -Wno-..., -Werror=...
  • #pragma GCC diagnostic push/pop
  • #pragma GCC system_header
  • -Wsystem-headers e supressão de cabeçalhos do sistema
C

Macros e semântica de pré-processamento

Macros de objeto, macros de função, argumentos vazios, macros variádicas, stringificação, token pasting e a extensão de eliminação de vírgula do GCC.

  • # e ##
  • __VA_OPT__(C++20)
  • , ## __VA_ARGS__
  • defined / __has_include
  • JSON de macro trace e análise do grafo de include
D

UCN e #embed

Universal character names participam de identificadores e de concatenação; #embed incorpora recursos binários conforme a semântica do GCC.

  • \uXXXX / \UXXXXXXXX
  • UCNs formados por barra invertida e quebra de linha
  • # / ## preserva a grafia UCN
  • #embed + limit
  • prefix / suffix / if_empty
  • gnu::offset e __has_embed
E

PCH e cache

GCC 13/14/15 podem usar a estratégia de PCH e o cache. O cache não interpreta o PCH do GCC diretamente: ele valida, registra, invalida e rastreia os arquivos externos no formato .gch.

  • --pch=ignore|warn|error|report
  • Layout de PCH do CMake com include forçado
  • Isolamento de caminho, versão e hash do compilador
  • Gravações atômicas, bloqueios de diretório, limpeza por capacidade e idade
  • JSON de estatísticas de taxa de acerto / stale / corrupt
F

Testes reproduzíveis

Três conjuntos de GCC, dois corpora diferenciais e projetos reais validam a saída em conjunto, não apenas se “o pré-processamento foi bem-sucedido”.

  • 65/65 no CTest para cada GCC15 / 14 / 13
  • differential corpus 13/13
  • realworld corpus 3/3
  • CrucibleCpp .i → GCC de destino → exe → execução
  • GCC g++.dg/cpp testsuite em regressão
Positioning

Ele substitui a etapa de pré-processamento, não o compilador

O CrucibleCpp não faz geração de código, não otimiza e não interpreta PCH binário do GCC. Sua única função é transformar arquivos-fonte em um .i, entregando diagnósticos, dependências e informações analisáveis ao sistema de build.
