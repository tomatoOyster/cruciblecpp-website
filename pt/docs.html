Instalação

Baixe o pacote do Windows x64 e descompacte em qualquer diretório. O CrucibleCpp é um programa de arquivo único vinculado estaticamente, então não é preciso instalar runtime.

cruciblecpp-preprocessor.exe --version # cruciblecpp-preprocessor 3.0.1
Alvo de produção atual: Windows x64 + MinGW-w64 UCRT64. Outras plataformas, ABIs e versões do GCC não têm suporte garantido.

Início rápido

Primeiro, confirme se o PATH contém o g++.exe. Depois, basta substituir o seu g++ -E:

# Pré-processa .\cruciblecpp-preprocessor.exe -P -std=c++20 src\main.cpp -o build\main.i # Compila com o mesmo GCC g++ -std=c++20 build\main.i -o build\main.exe

Se o GCC de destino não estiver no PATH, use --gcc para especificá-lo explicitamente:

.\cruciblecpp-preprocessor.exe ` --gcc "D:\GCC1413\gcc14\bin\g++.exe" ` -P -std=c++20 src\main.cpp -o build\main.i

Seleção do GCC

O CrucibleCpp usa as macros predefinidas do GCC de destino, os dados de __has_* e os caminhos de busca de include. Não use um perfil do GCC 15 para pré-processar cabeçalhos do GCC 14.

ModoComportamento
--gcc-version=13|14|15Procura no PATH o compilador mais alto suportado que corresponda à versão principal
--gcc <g++.exe>Usa diretamente o compilador especificado e lê sua versão e seus caminhos de include
Não especificadoVarre o PATH e escolhe por padrão a versão mais alta suportada (15 → 14 → 13)
A detecção automática verifica apenas o PATH. Se ele estiver instalado em outro diretório, adicione-o ao PATH ou use --gcc, e não dependa de uma letra de unidade fixa.

Perfis de padrão suportados:

-std=c++11 C++11 profile -std=c++14 C++14 profile -std=c++17 C++17 profile -std=c++20 C++20 profile

PCH

O g++ -E do GCC não usa .gch; o PCH só é usado na compilação real. Por padrão, o CrucibleCpp lê os cabeçalhos-fonte e, opcionalmente, valida, registra e armazena em cache PCHs gerados externamente.

# Emite um warning quando um .gch é encontrado --pch=warn # Falha imediatamente quando um .gch é encontrado --pch=error # Registra os PCHs ignorados no analysis JSON --pch=report

Ativar o cache de PCH:

.\cruciblecpp-preprocessor.exe ` --pch-cache .cache\pch ` --pch-cache-stats .cache\pch\stats.json ` -P src\main.cpp -o build\main.i

O manifesto do cache registra o caminho do compilador, a versão, o hash do compilador e o hash das opções. Os PCHs de GCC13/14/15 não colidem entre si.

Diagnósticos

Por padrão, emite linhas de código-fonte e caret no estilo GCC. Você pode desativar ou ajustar:

-fdiagnostics-color=auto|always|never -fno-diagnostics-show-caret -fno-diagnostics-show-option -Werror -Wno-error=name --max-errors 20

Suporta #pragma GCC diagnostic push/pop/ignored/warning/error e #pragma GCC system_header. Cabeçalhos provenientes de -isystem suprimem avisos comuns por padrão, e -Wsystem-headers pode exibi-los novamente.

Solução de problemas

Cabeçalhos da biblioteca padrão não encontrados

O compilador de destino não está no PATH. Use --gcc para especificá-lo, ou adicione seu diretório bin ao PATH. Você também pode usar -isystem para passá-lo explicitamente.

Versão errada do GCC selecionada

Use --gcc-version=13|14|15 para fixar a versão principal, ou use --gcc para apontar para o g++.exe. Não misture um perfil de destino com cabeçalhos de outra versão.

O cache de PCH acusa corrupt

O PCH não corresponde ao compilador/opções atuais, ou o arquivo está corrompido. Exclua a entrada de cache correspondente e regenere; alternativamente, desative o cache de PCH e deixe-o ler os cabeçalhos-fonte.

A saída não compila no GCC

Primeiro, confirme se o pré-processamento e a compilação usam a mesma versão do GCC e o mesmo -std. Em seguida, compile separadamente o “.i gerado pelo CrucibleCpp” para confirmar se o problema vem da etapa de pré-processamento.

O CrucibleCpp é um pré-processador, não um compilador. Ele não cuida de geração de código, otimização, linkedição nem da interpretação do formato interno do PCH binário do GCC.
