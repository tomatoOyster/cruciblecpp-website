Why CrucibleCpp

ไม่ใช่แค่ตัวขยายมาโครอีกตัว
แต่เป็นชั้นการประมวลผลล่วงหน้าที่ตรวจสอบได้

ทุกเคสทดสอบเชิงบวกผ่านห่วงโซ่เดียวกัน: CrucibleCpp สร้าง .i, ซึ่ง GCC ที่ตรงกันคอมไพล์เป็น exe แล้วรันจริง พฤติกรรมอ้างอิงจาก GCC 15.2, 14.3 และ 13.3

01

เวอร์ชันเป้าหมายชัดเจน

ใช้ --gcc-version หรือ --gcc เพื่อเลือกคอมไพเลอร์เป้าหมาย โปรไฟล์ มาโครในตัว และเส้นทาง include มาจากเป้าหมายเดียวกันทั้งหมด ไม่ผสมกัน

02

ไดแอกนอสติกสอดคล้องกับ GCC

ซอร์ส caret, include trace, warning ID,-Werror, สแตก pragma diagnostic และการระงับคำเตือนของส่วนหัวระบบ

03

ตรวจสอบกับโปรเจกต์จริง

nlohmann/json, fmt และ spdlog ผ่านการประมวลผลล่วงหน้า การคอมไพล์ และการรันบน GCC ทั้งสามเวอร์ชัน ครอบคลุมส่วนหัวและชุดมาโครจริง

04

UCN ครบถ้วน

\uXXXX และ \UXXXXXXXX มีส่วนร่วมในตัวระบุ,#, ## การตรวจสอบความถูกต้องและการปรับเอาต์พุตให้เป็นมาตรฐานสอดคล้องกับ GCC

05

#embed

การฝังข้อมูลไบนารี,limit, gnu::offset, prefix, suffix, if_empty และ __has_embed.

06

การแยก PCH ตามเวอร์ชัน

กลยุทธ์ PCH และแคชใช้ได้กับ GCC 13 / 14 / 15 ทั้งหมด manifest บันทึกเส้นทางคอมไพเลอร์ เวอร์ชัน และแฮชของไฟล์เรียกทำงาน เพื่อไม่ให้จับคู่ผิดข้ามเวอร์ชัน

Compatibility

เริ่มจากเมทริกซ์ที่ชัดเจน

เป้าหมายโปรดักชันปัจจุบันกำหนดไว้ที่ Windows x64 + MinGW-w64 UCRT64 โดย GCC แต่ละเวอร์ชันใช้โปรไฟล์และส่วนหัวของตนเอง และเอาต์พุตผ่านการตรวจสอบด้วยการคอมไพล์จริงด้วย GCC ที่ตรงกัน

เป้าหมายสถานะหมายเหตุ
GCC 15.2สมบูรณ์C++11/14/17/20 profile
GCC 14.3สมบูรณ์C++11/14/17/20 profile
GCC 13.3สมบูรณ์C++11/14/17/20 profile
Windows x64 / UCRT64รองรับเป้าหมายโปรดักชันปัจจุบัน
Linux / MSVC / Clangไม่รองรับสถาปัตยกรรมยังเปิดจุดขยายไว้
Test chain

การตรวจสอบไม่ใช่แค่ “ดูเหมือนว่ารันได้”

  • CTest สามชุดสำหรับ GCC15 / 14 / 13 ชุดละ 65/65
  • differential corpus 13/13: รหัสออก ไดแอกนอสติก และสตรีมโทเคน
  • realworld corpus 3/3: nlohmann/json, fmt, spdlog
  • ทุกเคสทดสอบเชิงบวกจะถูกรันจริงหลังสร้าง exe แล้ว
  • กลยุทธ์ PCH และแคชผ่านทั้งสามเวอร์ชัน
  • GCC g++.dg/cpp การทดสอบถดถอยด้วย testsuite อย่างต่อเนื่อง
