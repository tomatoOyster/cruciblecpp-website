Capabilities

ทำให้ทุกชั้นเป็น
พฤติกรรมที่ตรวจสอบได้

ตั้งแต่การเลือกเวอร์ชันเป้าหมาย มาโครที่กำหนดไว้ล่วงหน้า และไดแอกนอสติก ไปจนถึง PCH และโปรเจกต์จริง CrucibleCpp ไม่ได้ทำงานด้วยคำว่า “น่าจะได้” แต่ทำงานด้วยห่วงโซ่การทดสอบที่ทำซ้ำได้

A

เวอร์ชันเป้าหมายและโปรไฟล์

พรีโปรเซสเซอร์ตัวเดียว กับ GCC เป้าหมายสามเวอร์ชัน เลือกเวอร์ชันไหน ก็ได้มาโครที่กำหนดไว้ล่วงหน้าของเวอร์ชันนั้น,__has_* ข้อมูลและเส้นทางค้นหา include

  • --gcc-version=13|14|15
  • --gcc D:\path\to\g++.exe
  • ตรวจหา PATH อัตโนมัติ และเลือกเวอร์ชันสูงสุดที่รองรับเป็นค่าเริ่มต้น
  • GCC 13.3 / 14.3 / 15.2 profile
  • C++11 / C++14 / C++17 / C++20
B

ระบบไดแอกนอสติก

รูปแบบไดแอกนอสติกที่ออกแบบมาสำหรับระบบบิลด์จริง ประกอบด้วยบรรทัดซอร์ส caret, include trace และ warning option ไม่ใช่แค่สตริงข้อผิดพลาด

  • severity / option / caret แบบ GCC
  • -Werror, -Wno-..., -Werror=...
  • #pragma GCC diagnostic push/pop
  • #pragma GCC system_header
  • -Wsystem-headers และการระงับคำเตือนของส่วนหัวระบบ
C

มาโครและความหมายเชิงการประมวลผลล่วงหน้า

มาโครแบบออบเจกต์ มาโครแบบฟังก์ชัน พารามิเตอร์ว่าง มาโครแบบผันแปร stringification, token pasting และส่วนขยายการลบเครื่องหมายจุลภาคของ GCC

  • # และ ##
  • __VA_OPT__(C++20)
  • , ## __VA_ARGS__
  • defined / __has_include
  • macro trace และ JSON สำหรับวิเคราะห์กราฟ include
D

UCN และ #embed

Universal character name มีส่วนร่วมในตัวระบุและการต่อกัน; #embed ฝังทรัพยากรไบนารีตามความหมายของ GCC

  • \uXXXX / \UXXXXXXXX
  • UCN ที่เกิดจากแบ็กสแลชขึ้นบรรทัดใหม่
  • # / ## ยังคงรูปเขียน UCN ไว้
  • #embed + limit
  • prefix / suffix / if_empty
  • gnu::offset และ __has_embed
E

PCH และแคช

GCC 13/14/15 ใช้กลยุทธ์ PCH และแคชได้ทั้งหมด แคชไม่ได้แยกวิเคราะห์ PCH ของ GCC โดยตรง แต่จะตรวจสอบ ลงทะเบียน ทำให้หมดอายุ และติดตามไฟล์ภายนอก .gch.

  • --pch=ignore|warn|error|report
  • เลย์เอาต์ PCH ของ CMake ที่บังคับ include
  • การแยกเส้นทาง เวอร์ชัน และแฮชของคอมไพเลอร์
  • การเขียนแบบอะตอมมิก ล็อกไดเรกทอรี และการล้างตามขนาดและอายุ
  • JSON สถิติอัตราการเข้าถึง / stale / corrupt
F

การทดสอบที่ทำซ้ำได้

GCC สามชุด, differential corpus สองชุด และโปรเจกต์จริงร่วมกันตรวจสอบเอาต์พุต ไม่ได้ทดสอบแค่ว่า “การประมวลผลล่วงหน้าสำเร็จ”

  • GCC15 / 14 / 13 เวอร์ชันละ 65/65 CTest
  • differential corpus 13/13
  • realworld corpus 3/3
  • CrucibleCpp .i → GCC เป้าหมาย → exe → run
  • GCC g++.dg/cpp การทดสอบถดถอย testsuite
Positioning

มันแทนที่ขั้นตอนการประมวลผลล่วงหน้า ไม่ใช่คอมไพเลอร์

CrucibleCpp ไม่สร้างโค้ด ไม่ทำการปรับให้เหมาะสม และไม่แยกวิเคราะห์ PCH แบบไบนารีของ GCC หน้าที่เดียวของมันคือเปลี่ยนไฟล์ต้นฉบับให้เป็น .i, พร้อมส่งไดแอกนอสติก การพึ่งพา และข้อมูลที่วิเคราะห์ได้ให้กับระบบบิลด์
