ดาวน์โหลด V3.0.1
Documentation

เริ่มจากคำสั่งแรก

หน้านี้ครอบคลุมการติดตั้ง การเลือก GCC เป้าหมาย คำสั่งที่ใช้บ่อย PCH ไดแอกนอสติก และการแก้ปัญหา ส่วนรายละเอียดการใช้งานจริงและเมทริกซ์การทดสอบให้ยึดตามรีโป GitHub

ในหน้านี้

การติดตั้ง เริ่มต้นอย่างรวดเร็ว เลือก GCC บรรทัดคำสั่ง PCH ไดแอกนอสติก การแก้ปัญหา

การติดตั้ง

ดาวน์โหลดไฟล์ ZIP สำหรับ Windows x64 แล้วแตกไฟล์ไปยังไดเรกทอรีใดก็ได้ CrucibleCpp เป็นโปรแกรมไฟล์เดียวที่ลิงก์แบบสแตติก จึงไม่ต้องติดตั้งรันไทม์

cruciblecpp-preprocessor.exe --version # cruciblecpp-preprocessor 3.0.1
เป้าหมายโปรดักชันปัจจุบัน: Windows x64 + MinGW-w64 UCRT64 ส่วนแพลตฟอร์ม ABI และเวอร์ชัน GCC อื่นไม่ได้รับการรับประกันการรองรับ

เริ่มต้นอย่างรวดเร็ว

ขั้นแรกตรวจสอบว่ามี g++.exe ใน PATH แล้วแทนที่คำสั่ง g++ -E:

# ประมวลผลล่วงหน้า .\cruciblecpp-preprocessor.exe -P -std=c++20 src\main.cpp -o build\main.i # คอมไพล์ด้วย GCC ตัวเดียวกัน g++ -std=c++20 build\main.i -o build\main.exe

ถ้าไม่ได้ใส่ GCC เป้าหมายไว้ใน PATH ให้ใช้ --gcc ระบุอย่างชัดเจน:

.\cruciblecpp-preprocessor.exe ` --gcc "D:\GCC1413\gcc14\bin\g++.exe" ` -P -std=c++20 src\main.cpp -o build\main.i

เลือก GCC

CrucibleCpp ใช้มาโครที่กำหนดไว้ล่วงหน้าของ GCC เป้าหมาย,__has_* ข้อมูลและเส้นทางค้นหา include อย่าใช้โปรไฟล์ของ GCC15 ไปประมวลผลล่วงหน้าส่วนหัวของ GCC14

วิธีพฤติกรรม
--gcc-version=13|14|15ค้นหาคอมไพเลอร์ที่รองรับสูงสุดซึ่งตรงกับเวอร์ชันหลักใน PATH
--gcc <g++.exe>ใช้คอมไพเลอร์ที่ระบุโดยตรง และอ่านเวอร์ชันกับเส้นทาง include ของมัน
ไม่ระบุสแกน PATH และเลือกเวอร์ชันสูงสุดที่รองรับเป็นค่าเริ่มต้น (15 → 14 → 13)
การตรวจหาอัตโนมัติจะสแกนเฉพาะ PATH ถ้าติดตั้งไว้ในไดเรกทอรีอื่น ให้เพิ่มมันเข้าไปใน PATH หรือใช้ --gcc, อย่าพึ่งพาตัวอักษรไดรฟ์แบบตายตัว

โปรไฟล์มาตรฐานที่รองรับ:

-std=c++11 C++11 profile -std=c++14 C++14 profile -std=c++17 C++17 profile -std=c++20 C++20 profile

คำสั่งที่ใช้บ่อย

พารามิเตอร์หน้าที่
-Pไม่แสดง line markers
-o <file>ไฟล์เอาต์พุต
-I <dir>เพิ่มไดเรกทอรี include
-isystem <dir>ไดเรกทอรีส่วนหัวระบบ
-D / -Uกำหนด / ยกเลิกมาโคร
-include <file>บังคับ include
-MD -MF -MTสร้างไฟล์การพึ่งพาของ Make/CMake
-finput-charset / -fexec-charsetชุดอักขระอินพุต / เอ็กซีคิวชัน
--embed-dir <dir>#embed ไดเรกทอรีสำหรับค้นหา
--analysis-json <file>แสดงกราฟ include, มาโคร trace และบันทึก PCH

PCH

ตัว g++ -E ของ GCC ไม่ใช้ .gch; PCH ถูกใช้เฉพาะตอนคอมไพล์จริง CrucibleCpp อ่านซอร์สของส่วนหัวเป็นค่าเริ่มต้น และสามารถตรวจสอบ ลงทะเบียน และแคช PCH ที่สร้างจากภายนอกได้

# แจ้งคำเตือนเมื่อพบ .gch --pch=warn # รายงานข้อผิดพลาดทันทีเมื่อพบ .gch --pch=error # บันทึก PCH ที่ถูกละเลยลงใน analysis JSON --pch=report

เปิดใช้แคช PCH:

.\cruciblecpp-preprocessor.exe ` --pch-cache .cache\pch ` --pch-cache-stats .cache\pch\stats.json ` -P src\main.cpp -o build\main.i

manifest ของแคชจะบันทึกเส้นทางคอมไพเลอร์ เวอร์ชัน แฮชของคอมไพเลอร์ และแฮชของออปชัน PCH ของ GCC13/14/15 จะไม่จับคู่ผิดต่อกัน

ไดแอกนอสติก

โดยค่าเริ่มต้นจะแสดงบรรทัดซอร์สและ caret สไตล์ GCC สามารถปิดหรือปรับได้:

-fdiagnostics-color=auto|always|never -fno-diagnostics-show-caret -fno-diagnostics-show-option -Werror -Wno-error=name --max-errors 20

รองรับ #pragma GCC diagnostic push/pop/ignored/warning/error และ #pragma GCC system_header. ส่วนหัวที่มาจาก -isystem จะระงับคำเตือนทั่วไปโดยค่าเริ่มต้น และ -Wsystem-headers สามารถแสดงกลับมาได้

การแก้ปัญหา

ไม่พบส่วนหัวของไลบรารีมาตรฐาน

คอมไพเลอร์เป้าหมายไม่ได้อยู่ใน PATH ให้ใช้ --gcc เพื่อระบุ หรือเพิ่มไดเรกทอรี bin ของมันเข้าไปใน PATH หรือจะใช้ -isystem เพื่อระบุโดยตรง

เลือกเวอร์ชัน GCC ไม่ถูกต้อง

ใช้ --gcc-version=13|14|15 เพื่อล็อกเวอร์ชันหลัก หรือใช้ --gcc เพื่อชี้ไปที่ g++.exe. อย่าใช้ target profile ปนกับส่วนหัวของอีกเวอร์ชันหนึ่ง

แคช PCH รายงาน corrupt

PCH ไม่ตรงกับคอมไพเลอร์/ออปชันปัจจุบัน หรือไฟล์เสียหาย ให้ลบรายการแคชที่ตรงกันแล้วสร้างใหม่ หรือจะปิดแคช PCH ทั้งหมดแล้วให้อ่านซอร์สของส่วนหัวก็ได้

เอาต์พุตไม่สามารถคอมไพล์ด้วย GCC

ขั้นแรกตรวจสอบให้แน่ใจว่าการประมวลผลล่วงหน้าและการคอมไพล์ใช้ GCC เวอร์ชันเดียวกันและ -std. จากนั้นคอมไพล์ “.i ที่ CrucibleCpp สร้าง” แยกต่างหาก เพื่อตรวจสอบว่าปัญหามาจากขั้นตอนการประมวลผลล่วงหน้าหรือไม่

CrucibleCpp เป็นพรีโปรเซสเซอร์ ไม่ใช่คอมไพเลอร์ จึงไม่รับผิดชอบการสร้างโค้ด การปรับให้เหมาะสม การลิงก์ หรือการแยกวิเคราะห์รูปแบบภายในของ PCH แบบไบนารีของ GCC
