Capabilities

Rendi ogni livello
Comportamento verificabile

Dalla scelta della versione target alle macro predefinite e alla diagnostica, fino a PCH e progetti reali, CrucibleCpp non si basa sul “dovrebbe funzionare”, ma su una catena di test ripetibile.

A

Versione target e profilo

Un solo preprocessore, tre GCC target. La versione che scegli determina le macro predefinite, i dati di __has_* e i percorsi di ricerca degli include.

  • --gcc-version=13|14|15
  • --gcc D:\path\to\g++.exe
  • Rilevamento automatico nel PATH, con scelta predefinita della versione supportata più alta
  • GCC 13.3 / 14.3 / 15.2 profile
  • C++11 / C++14 / C++17 / C++20
B

Sistema di diagnostica

Un formato di diagnostica pensato per i sistemi di build reali. Include la riga di codice sorgente, il caret, l'include trace e l'opzione di warning, non solo una stringa di errore.

  • Severity / option / caret in stile GCC
  • -Werror, -Wno-..., -Werror=...
  • #pragma GCC diagnostic push/pop
  • #pragma GCC system_header
  • -Wsystem-headers e la soppressione degli header di sistema
C

Macro e semantica del preprocessing

Macro a oggetto, macro a funzione, argomenti vuoti, macro variadiche, stringification, token pasting e l'estensione GCC di eliminazione della virgola.

  • # e ##
  • __VA_OPT__(C++20)
  • , ## __VA_ARGS__
  • defined / __has_include
  • macro trace e analisi del grafo degli include in JSON
D

UCN e #embed

Gli universal character name partecipano agli identificatori e alla concatenazione; #embed incorpora risorse binarie secondo la semantica di GCC.

  • \uXXXX / \UXXXXXXXX
  • UCN formati da backslash e a capo
  • # / ## mantengono la grafia UCN
  • #embed + limit
  • prefix / suffix / if_empty
  • gnu::offset e __has_embed
E

PCH e cache

Con GCC 13/14/15 puoi usare la strategia e la cache PCH. La cache non analizza direttamente i PCH di GCC: convalida, registra, invalida e tiene traccia dei file esterni con estensione .gch.

  • --pch=ignore|warn|error|report
  • Layout PCH di CMake con include forzato
  • Isolamento per percorso, versione e hash del compilatore
  • Scritture atomiche, lock delle directory, pulizia per capacità ed età
  • JSON con statistiche hit rate / stale / corrupt
F

Test riproducibili

Tre toolchain GCC, due corpus differenziali e progetti reali convalidano insieme l'output, non solo il “preprocessing riuscito”.

  • GCC15 / 14 / 13: 65/65 CTest per ciascuna
  • differential corpus 13/13
  • realworld corpus 3/3
  • CrucibleCpp .i → GCC target → exe → esecuzione
  • GCC g++.dg/cpp testsuite in regressione continua
Positioning

Sostituisce la fase di preprocessing, non il compilatore

CrucibleCpp non genera codice, non ottimizza e non analizza i PCH binari di GCC. Il suo unico compito è trasformare i file sorgente in un file .i deterministico, affidando diagnostica, dipendenze e informazioni analizzabili al sistema di build.
