Capabilities

Convertimos cada capa en
comportamiento verificable

Desde la selección de la versión de destino y las macros predefinidas hasta los diagnósticos, el PCH y los proyectos reales, CrucibleCpp no se apoya en «debería funcionar», sino en una cadena de pruebas repetible.

A

Versión de destino y profile

Un solo preprocesador, tres GCC de destino. Elijas la versión que elijas, obtienes las macros predefinidas de esa versión,__has_* datos y rutas de búsqueda de include.

  • --gcc-version=13|14|15
  • --gcc D:\path\to\g++.exe
  • Detección automática de PATH, con la versión admitida más alta por defecto
  • GCC 13.3 / 14.3 / 15.2 profile
  • C++11 / C++14 / C++17 / C++20
B

Sistema de diagnósticos

Un formato de diagnóstico pensado para sistemas de compilación reales. Incluye la línea de código fuente, el caret, el include trace y la opción de advertencia, no solo una cadena de error.

  • severity / option / caret al estilo de GCC
  • -Werror, -Wno-..., -Werror=...
  • #pragma GCC diagnostic push/pop
  • #pragma GCC system_header
  • -Wsystem-headers y la supresión de cabeceras del sistema
C

Macros y semántica del preprocesamiento

Macros de objeto, macros de función, argumentos vacíos, macros variádicas, stringification, token pasting y la extensión de eliminación de comas de GCC.

  • # y ##
  • __VA_OPT__(C++20)
  • , ## __VA_ARGS__
  • defined / __has_include
  • JSON de macro trace y de análisis del grafo de include
D

UCN y #embed

Los universal character names intervienen en los identificadores y en la concatenación;#embed incrusta recursos binarios según la semántica de GCC.

  • \uXXXX / \UXXXXXXXX
  • UCN formados por barra invertida y salto de línea
  • # / ## conservan la grafía de las UCN
  • #embed + limit
  • prefix / suffix / if_empty
  • gnu::offset y __has_embed
E

PCH y caché

GCC 13/14/15 pueden usar la estrategia de PCH y la caché. La caché no analiza directamente los PCH de GCC, sino que valida, registra, invalida y rastrea los archivos .gch.

  • --pch=ignore|warn|error|report
  • Disposición de PCH de CMake con include forzado
  • aislamiento por ruta, versión y hash del compiler
  • Escrituras atómicas, bloqueos de directorio y limpieza por capacidad y antigüedad
  • JSON de estadísticas de tasa de aciertos / stale / corrupt
F

Pruebas reproducibles

Tres conjuntos de GCC, dos corpus diferenciales y proyectos reales validan conjuntamente la salida, no solo que «el preprocesamiento se haya completado».

  • GCC15 / 14 / 13: 65/65 CTest cada uno
  • differential corpus 13/13
  • realworld corpus 3/3
  • CrucibleCpp .i → GCC de destino → exe → run
  • GCC g++.dg/cpp regresión de testsuite
Positioning

Reemplaza el paso de preprocesamiento, no el compilador

CrucibleCpp no genera código, no optimiza y no analiza PCH binarios de GCC. Su única tarea es convertir los archivos de origen en un archivo determinista .i, entregando los diagnósticos, las dependencias y la información analizable al sistema de compilación.
