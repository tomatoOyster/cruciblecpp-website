دانلود V3.0.1
Capabilities

هر لایه را به
رفتار قابل تأیید تبدیل کنید

از انتخاب نسخه هدف و ماکروهای از پیش تعریف‌شده و تشخیص‌ها تا PCH و پروژه‌های واقعی، CrucibleCpp به «باید کار کند» تکیه نمی‌کند، بلکه به زنجیره‌ای قابل تکرار از آزمون‌ها.

A

نسخه هدف و پروفایل

یک پیش‌پردازنده، سه GCC هدف. هر نسخه‌ای را انتخاب کنید، ماکروهای از پیش تعریف‌شده، __has_* داده‌ها و مسیرهای جست‌وجوی include.

  • --gcc-version=13|14|15
  • --gcc D:\path\to\g++.exe
  • تشخیص خودکار PATH، انتخاب پیش‌فرض بالاترین نسخه پشتیبانی‌شده
  • GCC 13.3 / 14.3 / 15.2 profile
  • C++11 / C++14 / C++17 / C++20
B

سیستم تشخیص

قالب تشخیص متناسب با سیستم‌های ساخت واقعی. شامل سطر منبع، caret، include trace و warning option است، نه فقط یک رشته خطا.

  • severity / option / caret به سبک GCC
  • -Werror, -Wno-..., -Werror=...
  • #pragma GCC diagnostic push/pop
  • #pragma GCC system_header
  • -Wsystem-headers و سرکوب هدرهای سیستمی
C

ماکرو و معناشناسی پیش‌پردازش

ماکرو شیء، ماکرو تابع، آرگومان خالی، ماکرو متغیرآرگومان، رشته‌ای‌سازی، token pasting، و افزونه حذف کامای GCC.

  • # و ##
  • __VA_OPT__(C++20)
  • , ## __VA_ARGS__
  • defined / __has_include
  • JSON تحلیل macro trace و گراف include
D

UCN و #embed

نام‌های کاراکتر جهانی (Universal character name) در شناسه‌ها و چسباندن توکن‌ها نقش دارند؛ #embed منابع باینری را بر اساس معناشناسی GCC جاسازی می‌کند.

  • \uXXXX / \UXXXXXXXX
  • UCN ساخته‌شده از بک‌اسلش و شکستن خط
  • # / ## املای UCN در آن‌ها حفظ می‌شود
  • #embed + limit
  • prefix / suffix / if_empty
  • gnu::offset و __has_embed
E

PCH و کش

GCC 13/14/15 همه می‌توانند از سیاست PCH و کش استفاده کنند. کش به‌جای تجزیه مستقیم PCHهای GCC، فایل‌های خارجی با پسوند .gch.

  • --pch=ignore|warn|error|report
  • چیدمان PCH در CMake برای include اجباری
  • جداسازی مسیر، نسخه و هش compiler
  • نوشتن اتمی، قفل دایرکتوری، پاک‌سازی بر اساس حجم و سن
  • JSON آمار نرخ برخورد / stale / corrupt
F

آزمون‌های قابل بازتولید

سه مجموعه GCC، دو corpus تفاضلی و پروژه‌های واقعی خروجی را با هم تأیید می‌کنند، نه فقط «موفقیت پیش‌پردازش» را.

  • GCC15 / 14 / 13، هر یک 65/65 CTest
  • differential corpus 13/13
  • realworld corpus 3/3
  • CrucibleCpp .i → GCC هدف → exe → run
  • GCC g++.dg/cpp رگرسیون testsuite
Positioning

جایگزین آن مرحله پیش‌پردازش است، نه کامپایلر

CrucibleCpp تولید کد نمی‌کند، بهینه‌سازی انجام نمی‌دهد و PCH باینری GCC را تجزیه نمی‌کند. تنها کارش تبدیل فایل‌های منبع به فایل .i قطعی و سپردن تشخیص‌ها، وابستگی‌ها و اطلاعات قابل تحلیل به سیستم ساخت است.
