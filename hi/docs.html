पहली कमांड से शुरुआत करें

यह पृष्ठ इंस्टॉलेशन, लक्ष्य GCC चयन, सामान्य कमांड लाइन, PCH, निदान और समस्या निवारण को कवर करता है। पूरा कार्यान्वयन और परीक्षण मैट्रिक्स GitHub रिपॉज़िटरी में देखें।

इस पृष्ठ पर

इंस्टॉल त्वरित शुरुआत GCC का चयन कमांड लाइन PCH निदान समस्या निवारण

इंस्टॉल

Windows x64 का संग्रह डाउनलोड करें और किसी भी निर्देशिका में अनज़िप कर दें। CrucibleCpp स्टैटिक रूप से लिंक्ड एकल-फ़ाइल प्रोग्राम है; किसी रनटाइम की स्थापना आवश्यक नहीं।

cruciblecpp-preprocessor.exe --version # cruciblecpp-preprocessor 3.0.1
वर्तमान उत्पादन लक्ष्य: Windows x64 + MinGW-w64 UCRT64। अन्य प्लेटफ़ॉर्म, ABI और GCC संस्करणों के लिए समर्थन का वादा नहीं है।

त्वरित शुरुआत

पहले पुष्टि करें कि PATH में लक्ष्य g++.exe मौजूद है। फिर सीधे पुराने g++ -E:

# प्रीप्रोसेसिंग .\cruciblecpp-preprocessor.exe -P -std=c++20 src\main.cpp -o build\main.i # उसी GCC से संकलित करें g++ -std=c++20 build\main.i -o build\main.exe

अगर लक्ष्य GCC को PATH में नहीं रखा है, तो --gcc से स्पष्ट रूप से निर्दिष्ट करें:

.\cruciblecpp-preprocessor.exe ` --gcc "D:\GCC1413\gcc14\bin\g++.exe" ` -P -std=c++20 src\main.cpp -o build\main.i

GCC का चयन

CrucibleCpp लक्ष्य GCC के पूर्वनिर्धारित मैक्रो, __has_* डेटा और include खोज पथ उपयोग करता है। GCC15 की प्रोफ़ाइल से GCC14 की हेडर फ़ाइलें प्रीप्रोसेस न करें।

तरीकाव्यवहार
--gcc-version=13|14|15PATH में मेल खाते प्रमुख संस्करण वाला उच्चतम समर्थित कंपाइलर खोजता है
--gcc <g++.exe>निर्दिष्ट कंपाइलर का सीधे उपयोग करता है और उसका संस्करण तथा include पथ पढ़ता है
निर्दिष्ट नहींPATH स्कैन करता है, डिफ़ॉल्ट रूप से उच्चतम समर्थित संस्करण चुनता है (15 → 14 → 13)
स्वतः पहचान केवल PATH को स्कैन करती है। यदि इंस्टॉलेशन किसी अन्य निर्देशिका में है, तो उसे PATH में जोड़ें, या --gcc का उपयोग करें और किसी निश्चित ड्राइव अक्षर पर निर्भर न रहें।

समर्थित मानक प्रोफ़ाइल:

-std=c++11 C++11 profile -std=c++14 C++14 profile -std=c++17 C++17 profile -std=c++20 C++20 profile

सामान्य कमांड लाइन

पैरामीटरप्रभाव
-Pline markers आउटपुट नहीं करता
-o <file>आउटपुट फ़ाइल
-I <dir>include निर्देशिका जोड़ता है
-isystem <dir>सिस्टम हेडर निर्देशिका
-D / -Uमैक्रो परिभाषित / अपरिभाषित करें
-include <file>जबरन include
-MD -MF -MTMake/CMake निर्भरता फ़ाइलें बनाता है
-finput-charset / -fexec-charsetइनपुट / एक्ज़ीक्यूशन कैरेक्टर सेट
--embed-dir <dir>#embed खोज निर्देशिका
--analysis-json <file>include ग्राफ़, मैक्रो trace और PCH रिकॉर्ड आउटपुट करता है

PCH

GCC का g++ -E कमांड .gch फ़ाइलों का उपयोग नहीं करता; PCH केवल वास्तविक संकलन के समय उपयोग होता है। CrucibleCpp डिफ़ॉल्ट रूप से हेडर फ़ाइलों का स्रोत पढ़ता है और वैकल्पिक रूप से बाहर से बनाए गए PCH को सत्यापित, पंजीकृत और कैश करता है।

# .gch मिलने पर warning दें --pch=warn # .gch मिलने पर सीधे त्रुटि दें --pch=error # analysis JSON में अनदेखा किए गए PCH दर्ज करें --pch=report

PCH कैश सक्षम करें:

.\cruciblecpp-preprocessor.exe ` --pch-cache .cache\pch ` --pch-cache-stats .cache\pch\stats.json ` -P src\main.cpp -o build\main.i

कैश manifest में कंपाइलर का पथ, संस्करण, कंपाइलर हैश और विकल्प hash दर्ज होते हैं। GCC13/14/15 के PCH एक-दूसरे से गलत तरीके से नहीं मिलते।

निदान

डिफ़ॉल्ट रूप से GCC शैली की स्रोत पंक्तियाँ और caret आउटपुट होते हैं। इन्हें बंद या समायोजित किया जा सकता है:

-fdiagnostics-color=auto|always|never -fno-diagnostics-show-caret -fno-diagnostics-show-option -Werror -Wno-error=name --max-errors 20

इनका समर्थन है: #pragma GCC diagnostic push/pop/ignored/warning/error और #pragma GCC system_header। साथ ही -isystem से आने वाले हेडर डिफ़ॉल्ट रूप से सामान्य चेतावनियों को दबा देते हैं, -Wsystem-headers उन्हें फिर से दिखा सकता है।

समस्या निवारण

मानक लाइब्रेरी की हेडर फ़ाइल नहीं मिली

लक्ष्य कंपाइलर PATH में नहीं है। --gcc से निर्दिष्ट करें, या इसकी bin निर्देशिका PATH में जोड़ें। आप -isystem से स्पष्ट रूप से पास भी कर सकते हैं।

गलत GCC संस्करण चुना गया

प्रमुख संस्करण तय करने के लिए --gcc-version=13|14|15 का उपयोग करें, या --gcc से किसी विशिष्ट g++.exe की ओर इंगित करें। target profile को दूसरे संस्करण की हेडर फ़ाइलों के साथ न मिलाएँ।

PCH कैश corrupt की रिपोर्ट करता है

PCH वर्तमान कंपाइलर/विकल्पों से मेल नहीं खाता, या फ़ाइल खराब है। संबंधित कैश प्रविष्टि हटाकर फिर से जनरेट करें; या PCH कैश बंद कर दें, ताकि यह हेडर फ़ाइलों का स्रोत पढ़े।

आउटपुट GCC से संकलित नहीं होता

पहले पुष्टि करें कि प्रीप्रोसेसिंग और संकलन में एक ही GCC संस्करण और एक ही -std विकल्प उपयोग हो रहा है। फिर “CrucibleCpp से बनी .i” को अलग से संकलित करके जाँचें कि समस्या प्रीप्रोसेसिंग चरण से आ रही है या नहीं।

CrucibleCpp एक प्रीप्रोसेसर है, कंपाइलर नहीं। यह कोड जनरेशन, अनुकूलन, लिंकिंग और GCC के बाइनरी PCH के आंतरिक प्रारूप को पार्स करने के लिए ज़िम्मेदार नहीं है।
