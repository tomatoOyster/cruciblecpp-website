Documentation

Aloita ensimmäisestä komennosta

Tämä sivu kattaa asennuksen, kohde-GCC:n valinnan, yleisimmät komentorivit, PCH:n, diagnostiikan ja vianmäärityksen. Täydellinen toteutus ja testimatriisi ovat GitHub-varastossa.

Sisällys

Asennus Pika-aloitus GCC:n valinta Komentorivi PCH Diagnostiikka Vianmääritys

Asennus

Lataa Windows x64 -paketti ja pura se mihin tahansa hakemistoon. CrucibleCpp on staattisesti linkitetty yhden tiedoston ohjelma, joten ajonaikaista ei tarvitse asentaa.

cruciblecpp-preprocessor.exe --version # cruciblecpp-preprocessor 3.0.1
Nykyinen tuotantokohde: Windows x64 + MinGW-w64 UCRT64. Muita alustoja, ABI:a ja GCC-versioita ei luvata tukea.

Pika-aloitus

Varmista ensin, että PATHista löytyy g++.exe. Korvaa sitten suoraan vanha g++ -E:

# Esikäsittely .\cruciblecpp-preprocessor.exe -P -std=c++20 src\main.cpp -o build\main.i # Käännä samalla GCC:llä g++ -std=c++20 build\main.i -o build\main.exe

Jos kohde-GCC ei ole PATHissa, määritä se valitsimella --gcc eksplisiittisesti:

.\cruciblecpp-preprocessor.exe ` --gcc "D:\GCC1413\gcc14\bin\g++.exe" ` -P -std=c++20 src\main.cpp -o build\main.i

GCC:n valinta

CrucibleCpp käyttää kohde-GCC:n esimääriteltyjä makroja, __has_* tietoja ja include-hakupolkuja. Älä käytä GCC 15:n profiilia GCC 14:n otsikkotiedostojen esikäsittelyyn.

TapaToiminta
--gcc-version=13|14|15Etsii PATHista pääversiota vastaavan uusimman tuetun kääntäjän
--gcc <g++.exe>Käyttää annettua kääntäjää suoraan ja lukee sen version ja include-polut
Ei määritettySkannaa PATHin ja valitsee oletuksena uusimman tuetun version (15 → 14 → 13)
Automaattinen tunnistus skannaa vain PATHin. Jos ohjelma on asennettu muualle, lisää se PATHiin tai käytä valitsinta --gcc, äläkä luota kiinteään asemakirjaimeen.

Tuetut standardiprofiilit:

-std=c++11 C++11 profile -std=c++14 C++14 profile -std=c++17 C++17 profile -std=c++20 C++20 profile

PCH

GCC:n g++ -E ei käytä .gch; PCH:ta käytetään vain varsinaisessa käännöksessä. CrucibleCpp lukee oletuksena otsikkotiedostojen lähdekoodin ja voi halutessaan validoida, rekisteröidä ja tallentaa välimuistiin ulkoisesti luotuja PCH:ita.

# Varoita, kun .gch löytyy --pch=warn # Anna virhe heti, kun .gch löytyy --pch=error # Kirjaa ohitetut PCH:t analysis JSONiin --pch=report

Ota PCH-välimuisti käyttöön:

.\cruciblecpp-preprocessor.exe ` --pch-cache .cache\pch ` --pch-cache-stats .cache\pch\stats.json ` -P src\main.cpp -o build\main.i

Välimuistin manifesti tallentaa kääntäjän polun, version, kääntäjän hashin ja valitsimien hashin. GCC 13/14/15:n PCH:t eivät osu vahingossa toistensa kohdalle.

Diagnostiikka

Oletuksena tulostetaan GCC-tyyliset lähdekoodirivit ja caret. Voit poistaa ne käytöstä tai säätää niitä:

-fdiagnostics-color=auto|always|never -fno-diagnostics-show-caret -fno-diagnostics-show-option -Werror -Wno-error=name --max-errors 20

Tukee #pragma GCC diagnostic push/pop/ignored/warning/error ja #pragma GCC system_header. Valitsimella -isystem tuodut otsikkotiedostot vaimentavat oletuksena tavalliset varoitukset, ja -Wsystem-headers voi näyttää ne uudelleen.

Vianmääritys

Standardikirjaston otsikkotiedostoja ei löydy

Kohdekääntäjä ei ole PATHissa. Määritä se valitsimella --gcc tai lisää sen bin hakemisto PATHiin. Voit myös käyttää -isystem ja välittää sen eksplisiittisesti.

Väärä GCC-versio valittu

Kiinnitä pääversio valitsimella --gcc-version=13|14|15 tai osoita valitsimella --gcc suoraan tiedostoon g++.exe. Älä sekoita kohdeprofiilia toisen version otsikkotiedostoihin.

PCH-välimuisti ilmoittaa virheestä “corrupt”

PCH ei vastaa nykyistä kääntäjää tai valitsimia, tai tiedosto on vioittunut. Poista vastaava välimuistimerkintä ja luo se uudelleen; voit myös kytkeä PCH-välimuistin kokonaan pois, jolloin se lukee otsikkotiedostojen lähdekoodin.

Tulostetta ei voi kääntää GCC:llä

Varmista ensin, että esikäsittely ja käännös käyttävät samaa GCC-versiota ja samaa -std. Käännä sitten “CrucibleCpp:n tuottama .i” erikseen ja varmista, johtuuko ongelma esikäsittelyvaiheesta.

CrucibleCpp on esikäsittelijä, ei kääntäjä. Se ei vastaa koodin generoinnista, optimoinnista, linkityksestä eikä GCC:n binäärisen PCH-muodon sisäisen rakenteen jäsentämisestä.
