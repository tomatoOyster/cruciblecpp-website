Unduh V3.0.1
Capabilities

Membuat setiap lapisan
menjadi perilaku yang dapat diverifikasi

Dari pemilihan versi target, makro bawaan, dan diagnostik hingga PCH dan proyek nyata, CrucibleCpp tidak bekerja dengan asumsi “seharusnya bisa”, melainkan dengan rantai pengujian yang dapat diulang.

A

Versi target dan profil

Satu preprosesor, tiga GCC target. Versi mana pun yang Anda pilih, Anda memakai makro bawaan versi itu, __has_* data dan jalur pencarian include.

  • --gcc-version=13|14|15
  • --gcc D:\path\to\g++.exe
  • Deteksi otomatis PATH, secara default memilih versi tertinggi yang didukung
  • GCC 13.3 / 14.3 / 15.2 profile
  • C++11 / C++14 / C++17 / C++20
B

Sistem diagnostik

Format diagnostik yang dirancang untuk sistem build nyata. Memuat baris sumber, caret, include trace, dan warning option, bukan sekadar string galat.

  • severity / option / caret gaya GCC
  • -Werror, -Wno-..., -Werror=...
  • #pragma GCC diagnostic push/pop
  • #pragma GCC system_header
  • -Wsystem-headers dan penekanan header sistem
C

Makro dan semantik praproses

Makro objek, makro fungsi, argumen kosong, makro variadik, stringifikasi, token pasting, serta ekstensi penghapusan koma milik GCC.

  • # dan ##
  • __VA_OPT__(C++20)
  • , ## __VA_ARGS__
  • defined / __has_include
  • JSON analisis macro trace dan graf include
D

UCN dan #embed

Universal character name ikut serta dalam identifier dan penggabungan; #embed menyematkan sumber daya biner sesuai semantik GCC.

  • \uXXXX / \UXXXXXXXX
  • UCN yang terbentuk dari backslash-newline
  • # / ## tetap mempertahankan ejaan UCN
  • #embed + limit
  • prefix / suffix / if_empty
  • gnu::offset dan __has_embed
E

PCH dan cache

GCC 13/14/15 semuanya dapat memakai strategi PCH dan cache. Cache tidak mengurai PCH GCC secara langsung, melainkan memvalidasi, mencatat, membatalkan, dan melacak berkas .gch.

  • --pch=ignore|warn|error|report
  • Tata letak PCH CMake dengan include paksa
  • Isolasi jalur, versi, dan hash compiler
  • Penulisan atomik, kunci direktori, pembersihan berdasarkan kapasitas dan usia
  • JSON statistik hit rate / stale / corrupt
F

Pengujian yang dapat direproduksi

Tiga toolchain GCC, dua korpus diferensial, dan proyek nyata bersama-sama memvalidasi keluaran, bukan sekadar menguji “praproses berhasil”.

  • GCC15 / 14 / 13 masing-masing 65/65 CTest
  • differential corpus 13/13
  • realworld corpus 3/3
  • CrucibleCpp .i → GCC target → exe → run
  • GCC g++.dg/cpp Regresi testsuite
Positioning

Yang digantikan adalah langkah praproses, bukan compiler

CrucibleCpp tidak melakukan pembangkitan kode, tidak melakukan optimasi, dan tidak mengurai PCH biner GCC. Tugasnya hanya mengubah berkas sumber menjadi .i, serta menyerahkan diagnostik, dependensi, dan informasi yang dapat dianalisis kepada sistem build.
