Instalasi

Unduh arsip Windows x64 dan ekstrak ke direktori mana saja. CrucibleCpp adalah program satu berkas dengan linking statis, jadi tidak perlu memasang runtime.

cruciblecpp-preprocessor.exe --version # cruciblecpp-preprocessor 3.0.1
Target produksi saat ini: Windows x64 + MinGW-w64 UCRT64. Platform, ABI, dan versi GCC lain tidak dijamin didukung.

Mulai cepat

Pertama, pastikan PATH memuat g++.exe. Lalu cukup ganti g++ -E:

# Praproses .\cruciblecpp-preprocessor.exe -P -std=c++20 src\main.cpp -o build\main.i # Kompilasi dengan GCC yang sama g++ -std=c++20 build\main.i -o build\main.exe

Jika GCC target tidak ada di PATH, gunakan --gcc untuk menentukannya secara eksplisit:

.\cruciblecpp-preprocessor.exe ` --gcc "D:\GCC1413\gcc14\bin\g++.exe" ` -P -std=c++20 src\main.cpp -o build\main.i

Memilih GCC

CrucibleCpp memakai makro bawaan GCC target, __has_* data dan jalur pencarian include. Jangan memakai profil GCC15 untuk mempraproses header GCC14.

CaraPerilaku
--gcc-version=13|14|15Mencari compiler tertinggi yang didukung di PATH dengan versi utama yang cocok
--gcc <g++.exe>Memakai compiler yang ditentukan secara langsung dan membaca versi serta jalur include-nya
Tidak ditentukanPindai PATH, secara default pilih versi tertinggi yang didukung (15 → 14 → 13)
Deteksi otomatis hanya memindai PATH. Jika dipasang di direktori lain, tambahkan ke PATH, atau gunakan --gcc, dan jangan bergantung pada huruf drive tetap.

Profil standar yang didukung:

-std=c++11 C++11 profile -std=c++14 C++14 profile -std=c++17 C++17 profile -std=c++20 C++20 profile

PCH

Mode g++ -E milik GCC tidak memakai .gch; PCH hanya dipakai saat kompilasi sebenarnya. Secara default CrucibleCpp membaca sumber header, dan secara opsional dapat memvalidasi, mencatat, serta menyimpan dalam cache PCH yang dihasilkan secara eksternal.

# Beri peringatan saat .gch ditemukan --pch=warn # Langsung error saat .gch ditemukan --pch=error # Catat PCH yang diabaikan di analysis JSON --pch=report

Aktifkan cache PCH:

.\cruciblecpp-preprocessor.exe ` --pch-cache .cache\pch ` --pch-cache-stats .cache\pch\stats.json ` -P src\main.cpp -o build\main.i

Manifest cache mencatat jalur compiler, versi, hash compiler, dan hash opsi. PCH dari GCC13/14/15 tidak saling bertabrakan.

Diagnostik

Secara default menghasilkan baris sumber dan caret bergaya GCC. Anda dapat mematikan atau menyesuaikannya:

-fdiagnostics-color=auto|always|never -fno-diagnostics-show-caret -fno-diagnostics-show-option -Werror -Wno-error=name --max-errors 20

Mendukung #pragma GCC diagnostic push/pop/ignored/warning/error dan #pragma GCC system_header. Header yang berasal dari -isystem secara default menekan peringatan biasa, -Wsystem-headers dapat menampilkannya kembali.

Pemecahan masalah

Header pustaka standar tidak ditemukan

Compiler target tidak ada di PATH. Gunakan --gcc untuk menentukannya, atau tambahkan direktori bin ke PATH. Anda juga dapat menggunakan -isystem untuk meneruskannya secara eksplisit.

Versi GCC yang dipilih salah

Gunakan --gcc-version=13|14|15 untuk mematok versi utama, atau gunakan --gcc untuk menunjuk berkas g++.exe. Jangan mencampur profil target dengan header dari versi lain.

Cache PCH melaporkan corrupt

PCH tidak cocok dengan compiler/opsi saat ini, atau berkasnya rusak. Hapus entri cache yang sesuai lalu buat ulang; sebagai alternatif, matikan sepenuhnya cache PCH dan biarkan ia membaca sumber header.

Keluaran tidak dapat dikompilasi GCC

Pertama, pastikan praproses dan kompilasi memakai versi GCC yang sama dan -std. Lalu kompilasi “.i hasil CrucibleCpp” secara terpisah untuk memastikan apakah masalah berasal dari tahap praproses.

CrucibleCpp adalah preprosesor, bukan compiler. Ia tidak menangani pembangkitan kode, optimasi, linking, maupun penguraian format internal PCH biner GCC.
