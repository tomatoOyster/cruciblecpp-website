About the project

把“预处理”
变成可验证的一层

CrucibleCpp 从一个很具体的问题开始：当构建系统需要独立的预处理结果时，能不能不依赖 g++ -E 的进程调用，同时仍然得到可信、可解释、可回归的输出？

为什么是独立预处理器

预处理看起来只是“展开宏”，但真实项目会把它变成诊断、依赖、PCH、字符集、宏状态和构建缓存的交叉点。把它拆成独立层，才能单独观察、测试和优化。

CrucibleCpp 的目标不是重写编译器，而是把翻译阶段 1–4 做成一个边界清晰、行为可对照的组件。

设计原则

  • 行为以 GCC 为基准。 不是“看起来合理”，而是和真实 GCC 对照。
  • 每个正例都要编译运行。 预处理成功不等于输出可用。
  • 版本不混用。 目标 GCC 的 profile、头文件和编译命令必须一致。
  • 不隐藏限制。 未支持的能力明确写出，不用“应该可以”代替验证。
  • 先做 Windows x64。 先把一个目标做到可信，再谈跨平台。
