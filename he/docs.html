מהפקודה הראשונה

עמוד זה מכסה התקנה, בחירת GCC יעד, פקודות נפוצות, PCH, אבחונים ופתרון תקלות. המימוש המלא ומטריצת הבדיקות הם לפי מאגר ה-GitHub.

תוכן העמוד

התקנה התחלה מהירה בחירת GCC שורת פקודה PCH אבחונים פתרון תקלות

התקנה

הורידו את הארכיון של Windows x64 וחלצו אותו לכל ספרייה. CrucibleCpp הוא תוכנית בודדת המקושרת סטטית ואינה דורשת התקנת סביבת ריצה.

cruciblecpp-preprocessor.exe --version # cruciblecpp-preprocessor 3.0.1
יעד הייצור הנוכחי: Windows x64 + MinGW-w64 UCRT64. פלטפורמות, ABI וגרסאות GCC אחרות אינן נתמכות בהתחייבות.

התחלה מהירה

תחילה מוודאים שב-PATH נמצא קובץ g++.exe. ואז מחליפים ישירות את g++ -E:

# עיבוד מקדים .\cruciblecpp-preprocessor.exe -P -std=c++20 src\main.cpp -o build\main.i # הידור עם אותו GCC g++ -std=c++20 build\main.i -o build\main.exe

אם GCC היעד אינו ב-PATH, השתמשו באפשרות --gcc כדי לציין אותו במפורש:

.\cruciblecpp-preprocessor.exe ` --gcc "D:\GCC1413\gcc14\bin\g++.exe" ` -P -std=c++20 src\main.cpp -o build\main.i

בחירת GCC

CrucibleCpp משתמש במאקרואים המובנים של GCC היעד, __has_* והנתונים ונתיבי חיפוש include. אין להשתמש בפרופיל של GCC15 כדי לעבד מראש קובצי כותרת של GCC14.

שיטההתנהגות
--gcc-version=13|14|15מחפש ב-PATH את הקומפיילר הנתמך הגבוה ביותר התואם את הגרסה הראשית
--gcc <g++.exe>משתמש ישירות בקומפיילר שצוין וקורא את הגרסה ונתיבי ה-include שלו
לא צויןסורק את PATH ובוחר כברירת מחדל את הגרסה הנתמכת הגבוהה ביותר (15 → 14 → 13)
הזיהוי האוטומטי סורק רק את PATH. אם הוא מותקן בספרייה אחרת, הוסיפו אותה ל-PATH, או השתמשו באפשרות --gcc, ואל תסתמכו על אות כונן קבועה.

פרופילי תקן נתמכים:

-std=c++11 C++11 profile -std=c++14 C++14 profile -std=c++17 C++17 profile -std=c++20 C++20 profile

פקודות נפוצות

פרמטרמטרה
-Pללא פלט של line markers
-o <file>קובץ פלט
-I <dir>הוספת ספריית include
-isystem <dir>ספריית כותרות מערכת
-D / -Uהגדרה / ביטול הגדרה של מאקרו
-include <file>הכללה כפויה
-MD -MF -MTיצירת קובצי תלות Make/CMake
-finput-charset / -fexec-charsetערכת תווים לקלט / להרצה
--embed-dir <dir>#embed ספריית חיפוש
--analysis-json <file>פלט של גרף include, macro trace ורישומי PCH

PCH

הכלי g++ -E לא יעשה שימוש בקובצי .gch; קובצי PCH משמשים רק בהידור בפועל. CrucibleCpp קורא כברירת מחדל את קובצי הכותרת ממקור, ובאופן אופציונלי מאמת, רושם ומטמון קובצי PCH שנוצרו חיצונית.

# הצגת warning כאשר נמצא .gch --pch=warn # שגיאה מיידית כאשר נמצא .gch --pch=error # רישום PCH שלא נלקח בחשבון ב-analysis JSON --pch=report

הפעלת מטמון PCH:

.\cruciblecpp-preprocessor.exe ` --pch-cache .cache\pch ` --pch-cache-stats .cache\pch\stats.json ` -P src\main.cpp -o build\main.i

ה-manifest של המטמון מתעד נתיב קומפיילר, גרסה, גיבוב של הקומפיילר ו-hash של האפשרויות. קובצי PCH של GCC13/14/15 לא יפגעו זה בזה בטעות.

אבחונים

כברירת מחדל מוצגות שורות מקור בסגנון GCC ו-caret. אפשר לכבות או להתאים:

-fdiagnostics-color=auto|always|never -fno-diagnostics-show-caret -fno-diagnostics-show-option -Werror -Wno-error=name --max-errors 20

תומך בתחביר #pragma GCC diagnostic push/pop/ignored/warning/error ובתחביר #pragma GCC system_header. קובצי כותרת המגיעים מאפשרות -isystem מדכאים כברירת מחדל אזהרות רגילות, -Wsystem-headers מאפשר להציג אותן מחדש.

פתרון תקלות

לא נמצאו קובצי כותרת של ספריית התקן

קומפיילר היעד אינו ב-PATH. השתמשו באפשרות --gcc כדי לציין אותו, או הוסיפו את ספריית bin לנתיב ה-PATH. אפשר גם להשתמש באפשרות -isystem כדי להעביר במפורש.

נבחרה גרסת GCC שגויה

משתמשים באפשרות --gcc-version=13|14|15 כדי לקבע גרסה ראשית, או באפשרות --gcc כדי להצביע על g++.exe. אין לערבב פרופיל target עם קובצי כותרת של גרסה אחרת.

מטמון PCH מדווח corrupt

ה-PCH אינו תואם לקומפיילר או לאפשרויות הנוכחיות, או שהקובץ פגום. מחקו את רשומת המטמון המתאימה וצרו אותה מחדש; אפשר גם לכבות את מטמון ה-PCH כדי שייקראו קובצי הכותרת ממקור.

הפלט אינו ניתן להידור על ידי GCC

תחילה מוודאים שהעיבוד המקדים וההידור משתמשים באותה גרסת GCC ובאפשרות -std. לאחר מכן קמפלו בנפרד את קובץ ה-.i שנוצר על ידי CrucibleCpp, כדי לבדוק אם הבעיה מגיעה משלב העיבוד המקדים.

CrucibleCpp הוא קדם־מעבד, לא קומפיילר. הוא אינו אחראי ליצירת קוד, אופטימיזציה, קישור או פיענוח הפורמט הפנימי של קובצי PCH בינאריים של GCC.
