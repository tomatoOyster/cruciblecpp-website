Installation

Téléchargez l'archive Windows x64 et décompressez-la dans n'importe quel répertoire. CrucibleCpp est un programme monofichier lié statiquement : aucune installation de runtime n'est nécessaire.

cruciblecpp-preprocessor.exe --version # cruciblecpp-preprocessor 3.0.1
Cible de production actuelle : Windows x64 + MinGW-w64 UCRT64. Aucune prise en charge n'est garantie pour d'autres plateformes, ABI et versions de GCC.

Démarrage rapide

Vérifiez d'abord que le g++.exe cible se trouve bien dans PATH. Remplacez ensuite directement votre g++ -E:

# Prétraiter .\cruciblecpp-preprocessor.exe -P -std=c++20 src\main.cpp -o build\main.i # Compiler avec le même GCC g++ -std=c++20 build\main.i -o build\main.exe

Si le GCC cible n'est pas dans PATH, utilisez --gcc pour le spécifier explicitement :

.\cruciblecpp-preprocessor.exe ` --gcc "D:\GCC1413\gcc14\bin\g++.exe" ` -P -std=c++20 src\main.cpp -o build\main.i

Choisir GCC

CrucibleCpp utilise les macros prédéfinies du GCC cible et les données __has_* ainsi que les chemins de recherche d'include. N'utilisez pas un profil GCC 15 pour prétraiter les en-têtes de GCC 14.

MéthodeComportement
--gcc-version=13|14|15Recherche dans PATH le compilateur pris en charge le plus récent dont la version majeure correspond
--gcc <g++.exe>Utilise directement le compilateur indiqué et lit sa version et ses chemins d'include
Non spécifiéAnalyse PATH et retient par défaut la version prise en charge la plus élevée (15 → 14 → 13)
La détection automatique ne parcourt que PATH. Si l'installation se trouve dans un autre répertoire, ajoutez-le à PATH, ou utilisez --gcc, et ne comptez pas sur une lettre de lecteur fixe.

Profils standard pris en charge :

-std=c++11 C++11 profile -std=c++14 C++14 profile -std=c++17 C++17 profile -std=c++20 C++20 profile

PCH

L'option g++ -E de GCC n'utilise pas les .gch ; le PCH n'entre en jeu que lors de la compilation réelle. Par défaut, CrucibleCpp lit les sources des en-têtes et peut, en option, valider, enregistrer et mettre en cache les PCH générés en externe.

# Avertir lorsqu'un .gch est trouvé --pch=warn # Erreur immédiate lorsqu'un .gch est trouvé --pch=error # Journaliser les PCH ignorés dans le JSON d'analyse --pch=report

Activer le cache PCH :

.\cruciblecpp-preprocessor.exe ` --pch-cache .cache\pch ` --pch-cache-stats .cache\pch\stats.json ` -P src\main.cpp -o build\main.i

Le manifest du cache enregistre le chemin du compilateur, sa version, le hachage du compilateur et celui des options. Les PCH de GCC 13/14/15 ne se confondent pas entre eux.

Diagnostics

Génère par défaut les lignes de code source et le caret au style de GCC. Vous pouvez les désactiver ou les ajuster :

-fdiagnostics-color=auto|always|never -fno-diagnostics-show-caret -fno-diagnostics-show-option -Werror -Wno-error=name --max-errors 20

Prend en charge #pragma GCC diagnostic push/pop/ignored/warning/error et #pragma GCC system_header. Les en-têtes provenant de -isystem suppriment par défaut les avertissements ordinaires ; -Wsystem-headers permet de les réafficher.

Dépannage

En-têtes de la bibliothèque standard introuvables

Le compilateur cible n'est pas dans PATH. Utilisez --gcc pour le spécifier, ou ajoutez son répertoire bin à PATH. Vous pouvez aussi utiliser -isystem pour le passer explicitement.

Version de GCC choisie incorrecte

Utilisez --gcc-version=13|14|15 pour figer la version majeure, ou --gcc pour pointer vers un g++.exe. Ne mélangez pas un target profile avec les en-têtes d'une autre version.

Le cache PCH signale « corrupt »

Le PCH ne correspond pas au compilateur ni aux options actuels, ou le fichier est corrompu. Supprimez l'entrée de cache correspondante et régénérez-le ; vous pouvez aussi désactiver le cache PCH pour qu'il relise les sources des en-têtes.

Sortie impossible à compiler avec GCC

Vérifiez d'abord que le prétraitement et la compilation utilisent la même version de GCC et le même -std. Compilez ensuite séparément le « .i généré par CrucibleCpp » pour vérifier si le problème vient de la phase de prétraitement.

CrucibleCpp est un préprocesseur, pas un compilateur. Il ne prend en charge ni la génération de code, ni l'optimisation, ni l'édition de liens, ni l'analyse du format interne des PCH binaires de GCC.
