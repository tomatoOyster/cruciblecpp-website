Documentation

முதல் கட்டளையிலிருந்து தொடங்குங்கள்

இந்தப் பக்கம் நிறுவல், இலக்கு GCC தேர்வு, பொதுவான கட்டளை வரிகள், PCH, கண்டறிதல்கள் மற்றும் சிக்கல் தீர்வை உள்ளடக்குகிறது. முழுச் செயலாக்கமும் சோதனை அணியும் GitHub களஞ்சியத்தில் உள்ளபடியே அடிப்படையாகக் கொள்ளப்படும்.

இந்தப் பக்கத்தின் உள்ளடக்கம்

நிறுவல் விரைவு தொடக்கம் GCC தேர்வு கட்டளை வரி PCH கண்டறிதல் சிக்கல் தீர்வு

நிறுவல்

Windows x64 காப்பகத்தைப் பதிவிறக்கி, எந்த அடைவிலும் பிரித்தெடுத்தால் போதும். CrucibleCpp நிலையாக இணைக்கப்பட்ட ஒற்றைக் கோப்பு நிரல்; runtime நிறுவ வேண்டியதில்லை.

cruciblecpp-preprocessor.exe --version # cruciblecpp-preprocessor 3.0.1
தற்போதைய உற்பத்தி இலக்கு: Windows x64 + MinGW-w64 UCRT64. பிற தளங்கள், ABI மற்றும் GCC பதிப்புகளுக்கு ஆதரவு உறுதியளிக்கப்படவில்லை.

விரைவு தொடக்கம்

முதலில் PATHஇல் இலக்கு g++.exe கிடைப்பதை உறுதிசெய்யுங்கள். பின்னர் ஏற்கனவே உள்ள g++ -E:

# முன்செயலாக்கம் .\cruciblecpp-preprocessor.exe -P -std=c++20 src\main.cpp -o build\main.i # அதே GCC மூலம் தொகு g++ -std=c++20 build\main.i -o build\main.exe

இலக்கு GCCஐ PATHஇல் சேர்க்கவில்லை என்றால், --gcc மூலம் வெளிப்படையாகக் குறிப்பிடுங்கள்:

.\cruciblecpp-preprocessor.exe ` --gcc "D:\GCC1413\gcc14\bin\g++.exe" ` -P -std=c++20 src\main.cpp -o build\main.i

GCC தேர்வு

CrucibleCpp இலக்கு GCCவின் முன்வரையறுக்கப்பட்ட மேக்ரோக்கள், __has_* தகவல்கள் மற்றும் include தேடல் பாதைகளைப் பயன்படுத்துகிறது. GCC15 profileஐக் கொண்டு GCC14 தலைப்புக் கோப்புகளை முன்செயலாக்க வேண்டாம்.

முறைநடத்தை
--gcc-version=13|14|15PATHஇல் பொருந்தும் முக்கிய பதிப்பின் மிக உயர்ந்த ஆதரவுத் தொகுப்பியைத் தேடும்
--gcc <g++.exe>குறிப்பிட்ட தொகுப்பியை நேரடியாகப் பயன்படுத்தி, அதன் பதிப்பையும் include பாதையையும் படிக்கும்
குறிப்பிடவில்லைPATHஐ ஸ்கேன் செய்து, இயல்பாக மிக உயர்ந்த ஆதரவுப் பதிப்பைத் தேர்ந்தெடுக்கும் (15 → 14 → 13)
தானியங்கிக் கண்டறிதல் PATHஐ மட்டுமே ஸ்கேன் செய்யும். வேறு அடைவில் நிறுவியிருந்தால், அதை PATHஇல் சேர்க்கவும், அல்லது --gcc பயன்படுத்துங்கள்; நிலையான drive எழுத்தை நம்ப வேண்டாம்.

ஆதரவு பெறும் நிலையான profile வகைகள்:

-std=c++11 C++11 profile -std=c++14 C++14 profile -std=c++17 C++17 profile -std=c++20 C++20 profile

பொதுவான கட்டளை வரிகள்

அளவுருசெயல்
-Pline markers வெளியிடாது
-o <file>வெளியீட்டுக் கோப்பு
-I <dir>include அடைவைச் சேர்
-isystem <dir>கணினித் தலைப்பு அடைவு
-D / -Uமேக்ரோ வரையறு / நீக்கு
-include <file>கட்டாயச் சேர்ப்பு
-MD -MF -MTMake/CMake சார்புக் கோப்புகளை உருவாக்கு
-finput-charset / -fexec-charsetஉள்ளீடு / இயக்க எழுத்துத்தொகுப்பு
--embed-dir <dir>#embed தேடல் அடைவு
--analysis-json <file>include வரைபடம், மேக்ரோ trace, PCH பதிவுகளை வெளியிடு

PCH

GCCவின் g++ -E கட்டளை .gch கோப்புகளைப் பயன்படுத்துவதில்லை; PCH உண்மையான தொகுப்பின்போது மட்டுமே பயன்படும். CrucibleCpp இயல்பாக தலைப்புக் கோப்பு மூலங்களைப் படித்து, விருப்பத்தேர்வாக வெளிப்புறமாக உருவாக்கப்பட்ட PCHஐ சரிபார்த்து, பதிவு செய்து, cache செய்கிறது.

# .gch கண்டறியப்பட்டால் எச்சரிக்கை வெளியிடு --pch=warn # .gch கண்டறியப்பட்டால் நேரடியாகப் பிழை தெரிவி --pch=error # புறக்கணிக்கப்பட்ட PCHஐ analysis JSONஇல் பதிவு செய் --pch=report

PCH cacheஐ இயக்க:

.\cruciblecpp-preprocessor.exe ` --pch-cache .cache\pch ` --pch-cache-stats .cache\pch\stats.json ` -P src\main.cpp -o build\main.i

cache manifest தொகுப்பியின் பாதை, பதிப்பு, தொகுப்பி hash மற்றும் விருப்பங்களின் hash ஆகியவற்றைப் பதிவு செய்யும். GCC13/14/15 இன் PCH கோப்புகள் ஒன்றையொன்று தவறாக hit செய்யாது.

கண்டறிதல்

இயல்பாக GCC பாணியில் மூலக் குறியீட்டு வரியும் caret குறியீடும் வெளியிடப்படும். இதை மூடலாம் அல்லது மாற்றியமைக்கலாம்:

-fdiagnostics-color=auto|always|never -fno-diagnostics-show-caret -fno-diagnostics-show-option -Werror -Wno-error=name --max-errors 20

ஆதரவு: #pragma GCC diagnostic push/pop/ignored/warning/error மற்றும் #pragma GCC system_header. -isystem மூலம் வரும் தலைப்புகள் இயல்பாக சாதாரண எச்சரிக்கைகளை அடக்குகின்றன, -Wsystem-headers அவற்றை மீண்டும் காட்டும்.

சிக்கல் தீர்வு

நிலையான நூலகத் தலைப்புக் கோப்புகள் கிடைக்கவில்லை

இலக்கு தொகுப்பி PATHஇல் இல்லை. --gcc மூலம் குறிப்பிடுங்கள், அல்லது அதன் bin அடைவை PATHஇல் சேர்க்கவும். மேலும் -isystem மூலம் வெளிப்படையாக அனுப்பலாம்.

தவறான GCC பதிப்பு தேர்ந்தெடுக்கப்பட்டது

பயன்படுத்தி --gcc-version=13|14|15 முக்கிய பதிப்பை நிர்ணயிக்கவும், அல்லது --gcc மூலம் குறிப்பிட்ட g++.exeஐச் சுட்டுங்கள். target profileஐ வேறு பதிப்பின் தலைப்புக் கோப்புகளுடன் கலக்க வேண்டாம்.

PCH cache corrupt எனப் புகாரளிக்கிறது

PCH தற்போதைய தொகுப்பி/விருப்பங்களுடன் பொருந்தவில்லை, அல்லது கோப்பு சிதைந்துள்ளது. தொடர்புடைய cache உள்ளீட்டை நீக்கி மீண்டும் உருவாக்குங்கள்; அல்லது PCH cacheஐ முழுவதுமாக மூடிவிட்டு, அது தலைப்புக் கோப்பு மூலங்களைப் படிக்க விடுங்கள்.

வெளியீட்டை GCCஆல் தொகுக்க முடியவில்லை

முதலில் உறுதிசெய்யுங்கள்: முன்செயலாக்கமும் தொகுப்பும் ஒரே GCC பதிப்பையும் ஒரே -std. பின்னர் “CrucibleCpp உருவாக்கிய .i”ஐ தனியாகத் தொகுத்து, சிக்கல் முன்செயலாக்க நிலையிலிருந்து வருகிறதா என உறுதிசெய்யுங்கள்.

CrucibleCpp ஒரு முன்செயலி, தொகுப்பி அல்ல. குறியீட்டு உருவாக்கம், மேம்படுத்தல், இணைப்பு மற்றும் GCC பைனரி PCHஇன் உள் வடிவப் பாகுபடுத்தல் ஆகியவற்றுக்கு இது பொறுப்பல்ல.
