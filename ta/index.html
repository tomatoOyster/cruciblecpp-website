CrucibleCpp ஒரு தனித்த C++ முன்செயலி. இது மூலக் கோப்புகளைப் படித்து, மொழிபெயர்ப்பு நிலைகள் 1–4ஐ நிறைவு செய்து, GCC நேரடியாகத் தொடர்ந்து தொகுக்கக்கூடிய ஒரு .i கோப்பை உருவாக்குகிறது.

Why CrucibleCpp

மற்றொரு மேக்ரோ விரிவாக்கி அல்ல,
மாறாக சரிபார்க்கக்கூடிய முன்செயலாக்க அடுக்கு

ஒவ்வொரு நேர்மறை நிகழ்வும் ஒரே சங்கிலியைக் கடக்கிறது: CrucibleCpp உருவாக்கும் .i கோப்பை அந்தந்த GCC தொகுத்து exe ஆக மாற்றி, பின்னர் அதை உண்மையில் இயக்குகிறது. நடத்தை GCC 15.2, 14.3, 13.3 ஐ அடிப்படையாகக் கொண்டது.

01

தெளிவான இலக்கு பதிப்புகள்

பயன்படுத்தி --gcc-version அல்லது --gcc இலக்கு தொகுப்பியைத் தேர்ந்தெடுக்கலாம். profile, உள்ளமைந்த மேக்ரோக்கள் மற்றும் include பாதைகள் ஒரே இலக்கிலிருந்தே வரும்; கலக்கப்படுவதில்லை.

02

GCC கண்டறிதல்களுடன் ஒத்திசைவு

மூலக் குறியீட்டு caret, include trace, warning ID, -Werror, pragma diagnostic அடுக்கு, மேலும் கணினித் தலைப்புகளின் எச்சரிக்கை அடக்குதல்.

03

உண்மையான திட்டங்களில் சரிபார்ப்பு

nlohmann/json, fmt, spdlog ஆகியவை மூன்று GCC பதிப்புகளிலும் முன்செயலாக்கம், தொகுப்பு மற்றும் இயக்கம் ஆகியவற்றை நிறைவு செய்கின்றன; உண்மையான தலைப்புக் கோப்புகளையும் மேக்ரோ சேர்க்கைகளையும் உள்ளடக்குகின்றன.

04

முழுமையான UCN

\uXXXX மற்றும் \UXXXXXXXX அடையாளங்காட்டிகளிலும் #, ## பங்கேற்கின்றன; செல்லுபடித்தன்மைச் சரிபார்ப்பும் வெளியீட்டு இயல்பாக்கமும் GCC உடன் ஒத்துப்போகின்றன.

05

#embed

பைனரி உட்பொதித்தல், limit, gnu::offset, prefix, suffix, if_empty, மேலும் __has_embed.

06

PCH பதிப்புத் தனிமைப்படுத்தல்

GCC 13 / 14 / 15 மூன்றிலும் PCH கொள்கையும் cache வசதியும் கிடைக்கும். manifest தொகுப்பியின் பாதை, பதிப்பு மற்றும் இயக்கக்கூடிய கோப்பின் hash ஆகியவற்றைப் பதிவு செய்வதால், பதிப்புகளுக்கு இடையே தவறான cache hit ஏற்படாது.

Compatibility

தெளிவான அணியுடன் தொடங்குங்கள்

தற்போதைய உற்பத்தி இலக்கு Windows x64 + MinGW-w64 UCRT64 ஆகும். வெவ்வேறு GCC பதிப்புகள் தங்களுக்கான profile மற்றும் தலைப்புக் கோப்புகளைப் பயன்படுத்துகின்றன; வெளியீடு அந்தந்த GCC மூலம் உண்மையில் தொகுத்துச் சரிபார்க்கப்படுகிறது.

Test chain

சரிபார்ப்பு என்பது “இயங்குவது போல் தெரிவது” அல்ல

  • GCC15 / 14 / 13 ஆகியவற்றுக்கு மூன்று CTest தொகுப்புகள், ஒவ்வொன்றும் 65/65
  • differential corpus 13/13: வெளியேறும் குறியீடுகள், கண்டறிதல்கள், token ஓட்டம்
  • realworld corpus 3/3: nlohmann/json, fmt, spdlog
  • ஒவ்வொரு நேர்மறை நிகழ்வும் exe உருவான பிறகு உண்மையில் இயக்கப்படுகிறது
  • PCH policy மற்றும் cache மூன்று பதிப்புகளிலும் தேர்ச்சி பெறுகின்றன
  • GCC g++.dg/cpp testsuite தொடர்ச்சியான பின்னடைவுச் சோதனை
