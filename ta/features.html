V3.0.1 பதிவிறக்கு
Capabilities

ஒவ்வொரு அடுக்கையும்
சரிபார்க்கக்கூடிய நடத்தையாக ஆக்குங்கள்

இலக்கு பதிப்புத் தேர்வு, முன்வரையறுக்கப்பட்ட மேக்ரோக்கள், கண்டறிதல்கள் தொடங்கி PCH மற்றும் உண்மையான திட்டங்கள் வரை, CrucibleCpp “இது வேலை செய்ய வேண்டும்” என்ற நம்பிக்கையில் இயங்குவதில்லை; மீள்செய்யக்கூடிய சோதனைச் சங்கிலியையே நம்பியிருக்கிறது.

A

இலக்கு பதிப்பு மற்றும் profile

ஒரே முன்செயலி, மூன்று இலக்கு GCC. எந்தப் பதிப்பைத் தேர்ந்தெடுக்கிறீர்களோ, அந்தப் பதிப்பின் முன்வரையறுக்கப்பட்ட மேக்ரோக்கள், __has_* தகவல்கள் மற்றும் include தேடல் பாதைகளைப் பயன்படுத்துகிறது.

  • --gcc-version=13|14|15
  • --gcc D:\path\to\g++.exe
  • PATH தானியங்கிக் கண்டறிதல்; இயல்பாக மிக உயர்ந்த ஆதரவுப் பதிப்பு தேர்ந்தெடுக்கப்படும்
  • GCC 13.3 / 14.3 / 15.2 profile
  • C++11 / C++14 / C++17 / C++20
B

கண்டறிதல் முறைமை

உண்மையான கட்டமைப்பு முறைமைகளுக்கான கண்டறிதல் வடிவம். மூலக் குறியீட்டு வரி, caret, include trace மற்றும் warning option ஆகியவை அடங்கும்; வெறும் பிழைச் சரம் மட்டுமல்ல.

  • GCC பாணி severity / option / caret
  • -Werror, -Wno-..., -Werror=...
  • #pragma GCC diagnostic push/pop
  • #pragma GCC system_header
  • -Wsystem-headers மற்றும் கணினித் தலைப்பு அடக்குதல்
C

மேக்ரோ மற்றும் முன்செயலாக்க பொருளியல்

பொருள் மேக்ரோக்கள், செயல்பாட்டு மேக்ரோக்கள், காலி அளவுருக்கள், variadic மேக்ரோக்கள், stringification, token pasting, மேலும் GCCவின் கமா நீக்க நீட்டிப்பு.

  • # மற்றும் ##
  • __VA_OPT__(C++20)
  • , ## __VA_ARGS__
  • defined / __has_include
  • macro trace மற்றும் include வரைபடப் பகுப்பாய்வு JSON
D

UCN மற்றும் #embed

Universal character name அடையாளங்காட்டிகளிலும் இணைப்பிலும் பங்கேற்கிறது; #embed GCC பொருளியலின்படி பைனரி வளங்களை உட்பொதிக்கிறது.

  • \uXXXX / \UXXXXXXXX
  • பின்சாய்வுக் கோடு வரிமடிப்பால் உருவாகும் UCN
  • # / ## இல் UCN எழுத்துவடிவம் பாதுகாக்கப்படுகிறது
  • #embed + limit
  • prefix / suffix / if_empty
  • gnu::offset மற்றும் __has_embed
E

PCH மற்றும் cache

GCC 13/14/15 மூன்றிலும் PCH கொள்கையையும் cache வசதியையும் பயன்படுத்தலாம். cache என்பது GCC PCHஐ நேரடியாகப் பாகுபடுத்துவது அல்ல; மாறாக, வெளிப்புறமாக உருவாக்கப்பட்ட கோப்புகளைச் சரிபார்த்து, பதிவு செய்து, செல்லாததாக்கி, கண்காணிக்கிறது, எடுத்துக்காட்டாக .gch.

  • --pch=ignore|warn|error|report
  • includeஐக் கட்டாயமாக்கும் CMake PCH அமைப்பு
  • compiler பாதை, பதிப்பு, hash தனிமைப்படுத்தல்
  • அணு எழுத்து, அடைவுப் பூட்டு, கொள்ளளவு மற்றும் வயது அடிப்படையிலான அழிப்பு
  • hit rate / stale / corrupt புள்ளிவிவர JSON
F

மீளுருவாக்கக்கூடிய சோதனைகள்

மூன்று GCC தொகுப்புகள், இரண்டு differential corpus தொகுப்புகள் மற்றும் உண்மையான திட்டங்கள் இணைந்து வெளியீட்டைச் சரிபார்க்கின்றன; “முன்செயலாக்கம் வெற்றி” என்பதை மட்டும் சோதிப்பதில்லை.

  • GCC15 / 14 / 13 ஒவ்வொன்றுக்கும் 65/65 CTest
  • differential corpus 13/13
  • realworld corpus 3/3
  • CrucibleCpp .i → இலக்கு GCC → exe → run
  • GCC g++.dg/cpp testsuite பின்னடைவுச் சோதனை
Positioning

இது மாற்றுவது முன்செயலாக்கப் படிநிலையை, தொகுப்பியை அல்ல

CrucibleCpp குறியீட்டு உருவாக்கம் செய்வதில்லை, மேம்படுத்தல் செய்வதில்லை, GCC பைனரி PCHஐப் பாகுபடுத்துவதில்லை. மூலக் கோப்புகளை நிர்ணயமான ஒரு .i கோப்பாக மாற்றி, கண்டறிதல்கள், சார்புகள் மற்றும் பகுப்பாய்வு செய்யக்கூடிய தகவல்களை கட்டமைப்பு முறைமைக்கு வழங்குவதே அதன் பணி.
