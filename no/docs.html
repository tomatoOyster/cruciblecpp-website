Installasjon

Last ned Windows x64-arkivet og pakk det ut i en valgfri katalog. CrucibleCpp er et statisk lenket program i én enkelt fil, så det trengs ingen kjøretid.

cruciblecpp-preprocessor.exe --version # cruciblecpp-preprocessor 3.0.1
Gjeldende produksjonsmål: Windows x64 + MinGW-w64 UCRT64. Andre plattformer, ABI-er og GCC-versjoner er ikke garantert støttet.

Hurtigstart

Kontroller først at PATH inneholder riktig g++.exe. Erstatt deretter bare den opprinnelige g++ -E:

# Forbehandle .\cruciblecpp-preprocessor.exe -P -std=c++20 src\main.cpp -o build\main.i # Kompiler med samme GCC g++ -std=c++20 build\main.i -o build\main.exe

Hvis mål-GCC-en ikke er i PATH, bruk --gcc for å angi den eksplisitt:

.\cruciblecpp-preprocessor.exe ` --gcc "D:\GCC1413\gcc14\bin\g++.exe" ` -P -std=c++20 src\main.cpp -o build\main.i

Velg GCC

CrucibleCpp bruker mål-GCC-ens forhåndsdefinerte makroer, __has_* data og include-søkebaner. Ikke bruk en GCC15-profil til å forbehandle GCC14-headerfiler.

MetodeAtferd
--gcc-version=13|14|15Finn den høyeste støttede versjonen i PATH som samsvarer med hovedversjonen
--gcc <g++.exe>Bruk den angitte kompilatoren direkte og les versjonen og include-banene
Ikke angittSkann PATH og velg den høyeste støttede versjonen som standard (15 → 14 → 13)
Automatisk detektering skanner bare PATH. Hvis den er installert i en annen katalog, legger du den til i PATH, eller bruker --gcc, i stedet for å stole på en fast stasjonsbokstav.

Støttede standardprofiler:

-std=c++11 C++11 profile -std=c++14 C++14 profile -std=c++17 C++17 profile -std=c++20 C++20 profile

PCH

GCCs g++ -E bruker ikke .gch; PCH brukes bare ved faktisk kompilering. CrucibleCpp leser headerfilenes kildekode som standard og kan valgfritt validere, registrere og bufre eksternt genererte PCH-er.

# Varsle når en .gch oppdages --pch=warn # Gi feil direkte når en .gch oppdages --pch=error # Registrer ignorerte PCH-er i analysis JSON --pch=report

Aktiver PCH-hurtigbuffer:

.\cruciblecpp-preprocessor.exe ` --pch-cache .cache\pch ` --pch-cache-stats .cache\pch\stats.json ` -P src\main.cpp -o build\main.i

Hurtigbuffer-manifestet registrerer kompilatorbane, versjon, kompilatorhash og opsjonshash. PCH-er fra GCC13/14/15 kolliderer ikke med hverandre.

Diagnostikk

Som standard skrives GCC-lignende kildekodelinjer og caret ut. Du kan slå dette av eller justere det:

-fdiagnostics-color=auto|always|never -fno-diagnostics-show-caret -fno-diagnostics-show-option -Werror -Wno-error=name --max-errors 20

Støtter #pragma GCC diagnostic push/pop/ignored/warning/error og #pragma GCC system_header. Headere som kommer fra -isystem undertrykker vanlige advarsler som standard, -Wsystem-headers kan vise dem på nytt.

Feilsøking

Fant ikke headerfilene til standardbiblioteket

Målkompilatoren er ikke i PATH. Bruk --gcc eller legg til bin katalogen i PATH. Du kan også bruke -isystem for å sende den inn eksplisitt.

Feil GCC-versjon er valgt

Bruk --gcc-version=13|14|15 for å låse hovedversjonen, eller bruk --gcc for å peke på en bestemt g++.exe. Ikke bland en målprofil med headerfiler fra en annen versjon.

PCH-hurtigbufferen rapporterer corrupt

PCH-en samsvarer ikke med gjeldende kompilator/alternativer, eller filen er skadet. Slett den aktuelle hurtigbufferposten og generer den på nytt; du kan også slå av PCH-hurtigbufferen helt, slik at den leser headerfilenes kildekode.

GCC kan ikke kompilere utdataene

Kontroller først at forbehandlingen og kompileringen bruker samme GCC-versjon og -std. Kompiler deretter «.i»-filen som CrucibleCpp genererte, separat for å bekrefte om problemet kommer fra forbehandlingsfasen.

CrucibleCpp er en forprosessor, ikke en kompilator. Den håndterer ikke kodegenerering, optimalisering, lenking eller parsing av GCCs interne binære PCH-format.
