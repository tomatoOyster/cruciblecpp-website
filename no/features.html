Capabilities

Gjør hvert lag til
verifiserbar atferd

Fra valg av målversjon og forhåndsdefinerte makroer, via diagnostikk, til PCH og reelle prosjekter: CrucibleCpp bygger ikke på «det burde gå», men på en repeterbar testkjede.

A

Målversjon og profil

Én forprosessor, tre mål-GCC-er. Velger du en versjon, brukes den versjonens forhåndsdefinerte makroer, __has_* data og include-søkebaner.

  • --gcc-version=13|14|15
  • --gcc D:\path\to\g++.exe
  • Automatisk PATH-detektering, velger den høyeste støttede versjonen som standard
  • GCC 13.3 / 14.3 / 15.2 profile
  • C++11 / C++14 / C++17 / C++20
B

Diagnostikksystem

Diagnostikkformat for reelle byggesystemer. Inneholder kildelinje, caret, include trace og warning option – ikke bare en feilmelding.

  • GCC-stil severity / option / caret
  • -Werror, -Wno-..., -Werror=...
  • #pragma GCC diagnostic push/pop
  • #pragma GCC system_header
  • -Wsystem-headers og undertrykking av systemheadere
C

Makroer og forbehandlingssemantikk

Objektmakroer, funksjonsmakroer, tomme argumenter, variadiske makroer, stringifisering, token pasting og GCCs kommaelimineringsutvidelse.

  • # og ##
  • __VA_OPT__(C++20)
  • , ## __VA_ARGS__
  • defined / __has_include
  • JSON for macro trace og include-grafanalyse
D

UCN og #embed

Universal character name deltar i identifikatorer og sammenslåing; #embed bygger inn binære ressurser etter GCC-semantikk.

  • \uXXXX / \UXXXXXXXX
  • UCN dannet av backslash og linjeskift
  • # / ## beholder UCN-stavingen
  • #embed + limit
  • prefix / suffix / if_empty
  • gnu::offset og __has_embed
E

PCH og hurtigbuffer

PCH-strategi og hurtigbuffer kan brukes med GCC 13/14/15. Hurtigbufferen parser ikke GCC-PCH-er direkte, men validerer, registrerer, invaliderer og sporer eksterne .gch.

  • --pch=ignore|warn|error|report
  • CMake-PCH-oppsett med tvunget include
  • isolering av kompilatorbane, versjon og hash
  • atomiske skrivinger, kataloglås, opprydding etter størrelse og alder
  • JSON med statistikk for treffrate / stale / corrupt
F

Repeterbare tester

Tre GCC-versjoner, to differensielle korpora og reelle prosjekter verifiserer utdataene sammen – det testes ikke bare at «forbehandlingen lyktes».

  • GCC15 / 14 / 13: 65/65 CTest hver
  • differential corpus 13/13
  • realworld corpus 3/3
  • CrucibleCpp .i → mål-GCC → exe → run
  • GCC g++.dg/cpp testsuite-regresjon
Positioning

Det erstatter forbehandlingstrinnet, ikke kompilatoren

CrucibleCpp gjør ingen kodegenerering, ingen optimalisering og parser ikke binære PCH-er fra GCC. Den sørger bare for å gjøre kildefiler om til en deterministisk .i, og gir diagnostikk, avhengigheter og analyserbar informasjon til byggesystemet.
