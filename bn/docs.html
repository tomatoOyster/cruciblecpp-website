প্রথম কমান্ড থেকে শুরু

এই পৃষ্ঠায় ইনস্টলেশন, লক্ষ্য GCC নির্বাচন, সাধারণ কমান্ড লাইন, PCH, ডায়াগনস্টিক ও সমস্যা সমাধান কভার করা হয়েছে। সম্পূর্ণ বাস্তবায়ন ও পরীক্ষার ম্যাট্রিক্সের জন্য GitHub রিপোজিটরি প্রামাণ্য।

এই পৃষ্ঠায়

ইনস্টলেশন দ্রুত শুরু GCC নির্বাচন কমান্ড লাইন PCH ডায়াগনস্টিক সমস্যা সমাধান

ইনস্টলেশন

Windows x64 আর্কাইভ ডাউনলোড করে যেকোনো ডিরেক্টরিতে আনজিপ করলেই হবে। CrucibleCpp স্ট্যাটিকভাবে লিংক করা একক-ফাইল প্রোগ্রাম, তাই রানটাইম ইনস্টল করার প্রয়োজন নেই।

cruciblecpp-preprocessor.exe --version # cruciblecpp-preprocessor 3.0.1
বর্তমান প্রোডাকশন লক্ষ্য: Windows x64 + MinGW-w64 UCRT64। অন্যান্য প্ল্যাটফর্ম, ABI ও GCC সংস্করণের জন্য সমর্থনের প্রতিশ্রুতি নেই।

দ্রুত শুরু

প্রথমে নিশ্চিত করুন PATH-এ লক্ষ্য g++.exe পাওয়া যায়। তারপর সরাসরি প্রতিস্থাপন করুন পুরোনো g++ -E:

# প্রিপ্রসেস .\cruciblecpp-preprocessor.exe -P -std=c++20 src\main.cpp -o build\main.i # একই GCC দিয়ে কম্পাইল করুন g++ -std=c++20 build\main.i -o build\main.exe

যদি লক্ষ্য GCC PATH-এ না থাকে, --gcc দিয়ে স্পষ্টভাবে নির্দিষ্ট করুন:

.\cruciblecpp-preprocessor.exe ` --gcc "D:\GCC1413\gcc14\bin\g++.exe" ` -P -std=c++20 src\main.cpp -o build\main.i

GCC নির্বাচন

CrucibleCpp লক্ষ্য GCC-এর প্রি-ডিফাইনড ম্যাক্রো, __has_* ডেটা ও include সার্চ পাথ ব্যবহার করে। GCC15-এর প্রোফাইল দিয়ে GCC14-এর হেডার প্রিপ্রসেস করবেন না।

পদ্ধতিআচরণ
--gcc-version=13|14|15PATH-এ মিলে যাওয়া মেজর সংস্করণের সর্বোচ্চ সমর্থিত কম্পাইলার খোঁজে
--gcc <g++.exe>নির্দিষ্ট কম্পাইলার সরাসরি ব্যবহার করে এবং তার সংস্করণ ও include পাথ পড়ে
নির্দিষ্ট না করলেPATH স্ক্যান করে, ডিফল্টে সর্বোচ্চ সমর্থিত সংস্করণ বেছে নেয় (15 → 14 → 13)
স্বয়ংক্রিয় সনাক্তকরণ কেবল PATH স্ক্যান করে। অন্য ডিরেক্টরিতে ইনস্টল করা থাকলে সেটি PATH-এ যোগ করুন, অথবা ব্যবহার করুন --gcc। নির্দিষ্ট ড্রাইভ অক্ষরের ওপর নির্ভর করবেন না।

সমর্থিত স্ট্যান্ডার্ড প্রোফাইল:

-std=c++11 C++11 profile -std=c++14 C++14 profile -std=c++17 C++17 profile -std=c++20 C++20 profile

সাধারণ কমান্ড লাইন

প্যারামিটারকাজ
-Pline markers আউটপুট করে না
-o <file>আউটপুট ফাইল
-I <dir>include ডিরেক্টরি যোগ করে
-isystem <dir>সিস্টেম হেডার ডিরেক্টরি
-D / -Uম্যাক্রো ডিফাইন / আনডিফাইন
-include <file>বাধ্যতামূলক include
-MD -MF -MTMake/CMake ডিপেন্ডেন্সি ফাইল তৈরি করে
-finput-charset / -fexec-charsetইনপুট / এক্সিকিউশন ক্যারেক্টার সেট
--embed-dir <dir>#embed সার্চ ডিরেক্টরি
--analysis-json <file>include গ্রাফ, ম্যাক্রো trace, PCH রেকর্ড আউটপুট করে

PCH

GCC-এর g++ -E ব্যবহার করে না, যেমন .gch; PCH কেবল প্রকৃত কম্পাইলিংয়ের সময় ব্যবহৃত হয়। CrucibleCpp ডিফল্টে হেডার ফাইলের সোর্স পড়ে এবং ঐচ্ছিকভাবে বাইরে তৈরি PCH যাচাই, নিবন্ধন ও ক্যাশে করতে পারে।

# .gch পাওয়া গেলে warning দেখান --pch=warn # .gch পাওয়া গেলে সরাসরি ত্রুটি দিন --pch=error # analysis JSON-এ উপেক্ষিত PCH রেকর্ড করুন --pch=report

PCH ক্যাশে চালু করুন:

.\cruciblecpp-preprocessor.exe ` --pch-cache .cache\pch ` --pch-cache-stats .cache\pch\stats.json ` -P src\main.cpp -o build\main.i

ক্যাশে manifest কম্পাইলারের পাথ, সংস্করণ, কম্পাইলার হ্যাশ ও অপশন হ্যাশ রেকর্ড করে। GCC13/14/15-এর PCH একে অপরের সঙ্গে ভুলভাবে হিট করে না।

ডায়াগনস্টিক

ডিফল্টে GCC-শৈলীর সোর্স লাইন ও caret আউটপুট দেয়। বন্ধ বা সামঞ্জস্য করা যায়:

-fdiagnostics-color=auto|always|never -fno-diagnostics-show-caret -fno-diagnostics-show-option -Werror -Wno-error=name --max-errors 20

CrucibleCpp সমর্থন করে: #pragma GCC diagnostic push/pop/ignored/warning/error এবং #pragma GCC system_header। আর -isystem এর হেডার ডিফল্টে সাধারণ সতর্কতা দমন করে, -Wsystem-headers সেগুলো আবার দেখাতে পারে।

সমস্যা সমাধান

স্ট্যান্ডার্ড লাইব্রেরির হেডার পাওয়া যায় না

লক্ষ্য কম্পাইলার PATH-এ নেই। --gcc দিয়ে নির্দিষ্ট করুন, অথবা এর bin ডিরেক্টরি PATH-এ যোগ করুন। অথবা -isystem দিয়ে স্পষ্টভাবে পাস করুন।

ভুল GCC সংস্করণ নির্বাচিত হয়েছে

মেজর সংস্করণ নির্দিষ্ট করতে --gcc-version=13|14|15 ব্যবহার করুন, অথবা --gcc দিয়ে যে নির্দিষ্ট ফাইল বোঝায়: g++.exe। target profile-এর সঙ্গে অন্য সংস্করণের হেডার মেশাবেন না।

PCH ক্যাশে corrupt রিপোর্ট করে

PCH বর্তমান কম্পাইলার/অপশনের সঙ্গে মেলে না, অথবা ফাইলটি নষ্ট। সংশ্লিষ্ট ক্যাশে এন্ট্রি মুছে আবার তৈরি করুন; অথবা PCH ক্যাশে পুরোপুরি বন্ধ করে দিন, যাতে এটি হেডার ফাইলের সোর্স পড়ে।

আউটপুট GCC দিয়ে কম্পাইল করা যায় না

প্রথমে নিশ্চিত করুন প্রিপ্রসেসিং ও কম্পাইলিং একই GCC সংস্করণ ও -std ব্যবহার করছে। তারপর “CrucibleCpp-উৎপন্ন .i” আলাদাভাবে কম্পাইল করে দেখুন সমস্যাটি প্রিপ্রসেসিং পর্যায় থেকে আসছে কি না।

CrucibleCpp একটি প্রিপ্রসেসর, কম্পাইলার নয়। এটি কোড জেনারেশন, অপ্টিমাইজেশন, লিংকিং এবং GCC-এর বাইনারি PCH-এর অভ্যন্তরীণ ফরম্যাট পার্স করার দায়িত্ব বহন করে না।
