Capabilities

প্রতিটি স্তরকে
যাচাইযোগ্য আচরণে পরিণত করুন

লক্ষ্য সংস্করণ নির্বাচন, প্রি-ডিফাইনড ম্যাক্রো, ডায়াগনস্টিক থেকে PCH ও বাস্তব প্রকল্প পর্যন্ত, CrucibleCpp “এটা চলা উচিত” এই ভরসার ওপর নির্ভর করে না, বরং পুনরাবৃত্তিযোগ্য পরীক্ষা-শৃঙ্খলের ওপর নির্ভর করে।

A

লক্ষ্য সংস্করণ ও প্রোফাইল

একটি প্রিপ্রসেসর, তিনটি লক্ষ্য GCC। যে সংস্করণ বেছে নেবেন, সেই সংস্করণের প্রি-ডিফাইনড ম্যাক্রো, __has_* ডেটা ও include সার্চ পাথ ব্যবহার করে।

  • --gcc-version=13|14|15
  • --gcc D:\path\to\g++.exe
  • PATH স্বয়ংক্রিয় সনাক্তকরণ, ডিফল্টে সর্বোচ্চ সমর্থিত সংস্করণ নির্বাচন
  • GCC 13.3 / 14.3 / 15.2 profile
  • C++11 / C++14 / C++17 / C++20
B

ডায়াগনস্টিক সিস্টেম

বাস্তব বিল্ড সিস্টেমের জন্য ডায়াগনস্টিক ফরম্যাট। এতে সোর্স লাইন, caret, include trace ও warning option থাকে, শুধু একটি এরর স্ট্রিং নয়।

  • GCC-শৈলীর severity / option / caret
  • -Werror, -Wno-..., -Werror=...
  • #pragma GCC diagnostic push/pop
  • #pragma GCC system_header
  • -Wsystem-headers ও সিস্টেম হেডার দমন
C

ম্যাক্রো ও প্রিপ্রসেসিং সিম্যান্টিক্স

অবজেক্ট ম্যাক্রো, ফাংশন ম্যাক্রো, খালি আর্গুমেন্ট, ভ্যারিয়াডিক ম্যাক্রো, স্ট্রিংফিকেশন, token pasting, এবং GCC-এর কমা বাদ দেওয়ার এক্সটেনশন।

  • # এবং ##
  • __VA_OPT__(C++20)
  • , ## __VA_ARGS__
  • defined / __has_include
  • macro trace ও include গ্রাফ বিশ্লেষণ JSON
D

UCN ও #embed

Universal character name আইডেন্টিফায়ার ও সংযোজনে অংশ নেয়; #embed GCC সিম্যান্টিক্স অনুযায়ী বাইনারি রিসোর্স এমবেড করে।

  • \uXXXX / \UXXXXXXXX
  • ব্যাকস্ল্যাশ-নিউলাইনে গঠিত UCN
  • # / ## এর মধ্যে UCN বানান সংরক্ষিত থাকে
  • #embed + limit
  • prefix / suffix / if_empty
  • gnu::offset এবং __has_embed
E

PCH ও ক্যাশে

GCC 13/14/15 모두 PCH কৌশল ও ক্যাশে ব্যবহার করতে পারে। ক্যাশে GCC PCH সরাসরি পার্স করে না, বরং বাইরের ফাইল যাচাই, নিবন্ধন, অকার্যকরকরণ ও ট্র্যাকিং করে — .gch.

  • --pch=ignore|warn|error|report
  • বাধ্যতামূলক include সহ CMake PCH লেআউট
  • কম্পাইলার পাথ, সংস্করণ ও হ্যাশ বিচ্ছিন্নতা
  • অ্যাটমিক রাইট, ডিরেক্টরি লক, ক্যাপাসিটি ও বয়স অনুযায়ী পরিষ্কার
  • হিট রেট / stale / corrupt পরিসংখ্যান JSON
F

পুনরুৎপাদনযোগ্য পরীক্ষা

তিনটি GCC সেট, দুটি differential করপাস ও বাস্তব প্রকল্প একসঙ্গে আউটপুট যাচাই করে, শুধু “প্রিপ্রসেসিং সফল” পরীক্ষা করে না।

  • GCC15 / 14 / 13 প্রতিটিতে 65/65 CTest
  • differential corpus 13/13
  • realworld corpus 3/3
  • CrucibleCpp .i → লক্ষ্য GCC → exe → রান
  • GCC g++.dg/cpp testsuite রিগ্রেশন
Positioning

এটি প্রিপ্রসেসিং ধাপের বিকল্প, কম্পাইলারের নয়

CrucibleCpp কোড জেনারেশন করে না, অপ্টিমাইজ করে না, GCC-এর বাইনারি PCH পার্স করে না। এর একমাত্র কাজ সোর্স ফাইল থেকে একটি নির্ধারক .i তৈরি করা এবং ডায়াগনস্টিক, নির্ভরতা ও বিশ্লেষণযোগ্য তথ্য বিল্ড সিস্টেমের হাতে দেওয়া।
