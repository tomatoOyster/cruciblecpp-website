Installation

Laden Sie das Windows-x64-Archiv herunter und entpacken Sie es in ein beliebiges Verzeichnis. CrucibleCpp ist ein statisch gelinktes Einzeldatei-Programm; eine Laufzeitumgebung muss nicht installiert werden.

cruciblecpp-preprocessor.exe --version # cruciblecpp-preprocessor 3.0.1
Aktuelles Produktionsziel: Windows x64 + MinGW-w64 UCRT64. Andere Plattformen, ABIs und GCC-Versionen werden nicht zugesichert.

Schnellstart

Suchen Sie im PATH nach g++.exe. Ersetzen Sie dann einfach Ihr bisheriges g++ -E:

# Vorverarbeitung .\cruciblecpp-preprocessor.exe -P -std=c++20 src\main.cpp -o build\main.i # Mit demselben GCC kompilieren g++ -std=c++20 build\main.i -o build\main.exe

Wenn der Ziel-GCC nicht im PATH liegt, geben Sie ihn mit --gcc explizit an:

.\cruciblecpp-preprocessor.exe ` --gcc "D:\GCC1413\gcc14\bin\g++.exe" ` -P -std=c++20 src\main.cpp -o build\main.i

GCC wählen

CrucibleCpp nutzt die vordefinierten Makros des Ziel-GCC, die__has_* Daten und die Include-Suchpfade. Verwenden Sie kein GCC-15-Profil, um Header von GCC 14 zu verarbeiten.

MethodeVerhalten
--gcc-version=13|14|15Sucht im PATH den höchsten unterstützten Compiler, der zur Hauptversion passt
--gcc <g++.exe>Verwendet den angegebenen Compiler direkt und liest dessen Version und Include-Pfade
Nicht angegebenDurchsucht den PATH und wählt standardmäßig die höchste unterstützte Version (15 → 14 → 13)
Die automatische Erkennung durchsucht nur den PATH. Bei einer Installation in einem anderen Verzeichnis nehmen Sie es in den PATH auf oder verwenden Sie --gcc, und verlassen Sie sich nicht auf einen festen Laufwerksbuchstaben.

Unterstützte Standardprofile:

-std=c++11 C++11 profile -std=c++14 C++14 profile -std=c++17 C++17 profile -std=c++20 C++20 profile

PCH

GCCs g++ -E nutzt .gchnicht; PCH wird erst beim eigentlichen Kompilieren verwendet. CrucibleCpp liest standardmäßig die Header-Quellen und kann extern erzeugte PCHs optional validieren, registrieren und cachen.

# Warnung ausgeben, wenn eine .gch gefunden wird --pch=warn # Sofort mit Fehler abbrechen, wenn eine .gch gefunden wird --pch=error # Ignorierte PCHs im Analysis-JSON erfassen --pch=report

PCH-Cache aktivieren:

.\cruciblecpp-preprocessor.exe ` --pch-cache .cache\pch ` --pch-cache-stats .cache\pch\stats.json ` -P src\main.cpp -o build\main.i

Das Cache-Manifest zeichnet Compiler-Pfad, Version, Compiler-Hash und Options-Hash auf. PCHs von GCC 13/14/15 kollidieren nicht miteinander.

Diagnosen

Standardmäßig werden GCC-artige Quellzeilen und Caret ausgegeben. Das lässt sich abschalten oder anpassen:

-fdiagnostics-color=auto|always|never -fno-diagnostics-show-caret -fno-diagnostics-show-option -Werror -Wno-error=name --max-errors 20

Unterstützt #pragma GCC diagnostic push/pop/ignored/warning/error und #pragma GCC system_header. Header aus -isystem unterdrücken standardmäßig normale Warnungen;-Wsystem-headers macht sie wieder sichtbar.

Fehlerbehebung

Standardbibliotheks-Header nicht gefunden

Der Ziel-Compiler ist nicht im PATH. Geben Sie ihn mit --gcc an, oder fügen Sie bin zum PATH hinzu. Alternativ können Sie -isystem explizit übergeben.

Falsche GCC-Version gewählt

Fixieren Sie die Hauptversion mit --gcc-version=13|14|15 , oder verweisen Sie mit --gcc gezielt auf eine bestimmte g++.exe. Mischen Sie kein Zielprofil mit Headern einer anderen Version.

PCH-Cache meldet corrupt

PCH und aktueller Compiler bzw. die Optionen passen nicht zusammen, oder die Datei ist beschädigt. Löschen Sie den passenden Cache-Eintrag und erzeugen Sie ihn neu; alternativ deaktivieren Sie den PCH-Cache und lassen Sie die Header-Quellen lesen.

Die Ausgabe lässt sich nicht mit GCC kompilieren

Prüfen Sie zuerst, ob Vorverarbeitung und Kompilierung dieselbe GCC-Version und -std. Kompilieren Sie dann die von CrucibleCpp erzeugte „.i“ separat, um zu prüfen, ob das Problem aus der Vorverarbeitungsphase stammt.

CrucibleCpp ist ein Präprozessor, kein Compiler. Er ist nicht für Codegenerierung, Optimierung, Linken oder das Parsen des internen binären PCH-Formats von GCC zuständig.
