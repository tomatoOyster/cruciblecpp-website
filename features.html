Capabilities

把每一层都做成
可验证的行为

从目标版本选择、预定义宏、诊断，到 PCH 和真实项目，CrucibleCpp 不靠“应该可以”工作，而是靠可重复的测试链路。

A

目标版本与 profile

一套预处理器，三种目标 GCC。选择哪个版本，就使用哪个版本的预定义宏、__has_* 数据和 include 搜索路径。

  • --gcc-version=13|14|15
  • --gcc D:\path\to\g++.exe
  • PATH 自动检测，默认选择最高支持版本
  • GCC 13.3 / 14.3 / 15.2 profile
  • C++11 / C++14 / C++17 / C++20
B

诊断系统

面向真实构建系统的诊断格式。包含源码行、caret、include trace 和 warning option，不只是一个错误字符串。

  • GCC 风格 severity / option / caret
  • -Werror、-Wno-...、-Werror=...
  • #pragma GCC diagnostic push/pop
  • #pragma GCC system_header
  • -Wsystem-headers 与系统头抑制
C

宏与预处理语义

对象宏、函数宏、空参数、可变参数宏、字符串化、token pasting，以及 GCC 的逗号消除扩展。

  • # 与 ##
  • __VA_OPT__（C++20）
  • , ## __VA_ARGS__
  • defined / __has_include
  • macro trace 与 include 图分析 JSON
D

UCN 与 #embed

Universal character name 参与标识符和拼接；#embed 按 GCC 语义嵌入二进制资源。

  • \uXXXX / \UXXXXXXXX
  • 反斜杠换行形成的 UCN
  • # / ## 中保留 UCN 拼写
  • #embed + limit
  • prefix / suffix / if_empty
  • gnu::offset 与 __has_embed
E

PCH 与缓存

GCC 13/14/15 都能使用 PCH 策略和缓存。缓存不是直接解析 GCC PCH，而是验证、登记、失效并追踪外部 .gch。

  • --pch=ignore|warn|error|report
  • 强制 include 的 CMake PCH 布局
  • compiler 路径、版本、哈希隔离
  • 原子写入、目录锁、容量和年龄清理
  • 命中率 / stale / corrupt 统计 JSON
F

可复现的测试

三套 GCC、两个差分语料库和真实项目共同验证输出，不只测试“预处理成功”。

  • GCC15 / 14 / 13 各 65/65 CTest
  • differential corpus 13/13
  • realworld corpus 3/3
  • CrucibleCpp .i → 目标 GCC → exe → run
  • GCC g++.dg/cpp testsuite 回归
Positioning

它替代的是预处理步骤，不是编译器

CrucibleCpp 不做代码生成、不做优化、不解析 GCC 二进制 PCH。它只负责把源文件变成确定的 .i，把诊断、依赖和可分析信息交给构建系统。
