Descărcați V3.0.1
Capabilities

Transformăm fiecare nivel în
comportament verificabil

De la alegerea versiunii țintă, macrocomenzile predefinite și diagnostice, până la PCH și proiecte reale, CrucibleCpp nu se bazează pe „ar trebui să meargă”, ci pe un lanț de testare reproductibil.

A

Versiuni țintă și profil

Un singur preprocesor, trei GCC țintă. Indiferent de versiunea aleasă, folosiți macrocomenzile predefinite, datele __has_* și căile de căutare include.

  • --gcc-version=13|14|15
  • --gcc D:\path\to\g++.exe
  • Detectare automată în PATH, cu selectarea implicită a celei mai noi versiuni acceptate
  • GCC 13.3 / 14.3 / 15.2 profile
  • C++11 / C++14 / C++17 / C++20
B

Sistem de diagnostice

Format de diagnostic gândit pentru sisteme de build reale. Include linia sursă, caret, include trace și opțiunea de avertisment, nu doar un șir de eroare.

  • Severitate / opțiune / caret în stil GCC
  • -Werror, -Wno-..., -Werror=...
  • #pragma GCC diagnostic push/pop
  • #pragma GCC system_header
  • -Wsystem-headers și suprimarea antetelor de sistem
C

Macrocomenzi și semantica preprocesării

Macrocomenzi obiect, macrocomenzi funcție, argumente goale, macrocomenzi variadice, stringificare, token pasting și extensia GCC de eliminare a virgulei.

  • # și ##
  • __VA_OPT__(C++20)
  • , ## __VA_ARGS__
  • defined / __has_include
  • macro trace și analiză JSON a grafului de include
D

UCN și #embed

Universal character name participă la identificatori și la concatenare;#embed încorporează resurse binare conform semanticii GCC.

  • \uXXXX / \UXXXXXXXX
  • UCN format din bară oblică inversă și newline
  • # / ## păstrează grafia UCN
  • #embed + limit
  • prefix / suffix / if_empty
  • gnu::offset și __has_embed
E

PCH și cache

GCC 13/14/15 pot folosi toate politicile PCH și cache-ul. Cache-ul nu analizează direct PCH-urile GCC, ci validează, înregistrează, invalidează și urmărește fișierele externe .gch.

  • --pch=ignore|warn|error|report
  • Layout CMake PCH cu include forțat
  • Izolare după calea, versiunea și hash-ul compilatorului
  • Scriere atomică, blocare pe director, curățare după capacitate și vechime
  • Statistici JSON pentru rata de potrivire / stale / corrupt
F

Teste reproductibile

Trei suite GCC, două corpusuri diferențiale și proiecte reale validează împreună rezultatul, nu doar „preprocesarea a reușit”.

  • GCC15 / 14 / 13, câte 65/65 CTest
  • differential corpus 13/13
  • realworld corpus 3/3
  • CrucibleCpp .i → GCC țintă → exe → run
  • GCC g++.dg/cpp testsuite: regresie
Positioning

Înlocuiește pasul de preprocesare, nu compilatorul

CrucibleCpp nu generează cod, nu optimizează și nu analizează PCH-uri binare GCC. Se ocupă doar de transformarea fișierelor sursă în .i deterministe și de predarea către sistemul de build a diagnosticelor, dependențelor și informațiilor analizabile.
