Завантажити V3.0.1

перевірюваною поведінкою

Від вибору цільової версії, попередньо визначених макросів і діагностики до PCH і реальних проєктів — CrucibleCpp працює не за принципом «мабуть, спрацює», а завдяки відтворюваному ланцюжку тестів.

A

Цільові версії та профілі

Один препроцесор, три цільові GCC. Обрана версія визначає попередньо визначені макроси та __has_* дані, а також шляхи пошуку include.

  • --gcc-version=13|14|15
  • --gcc D:\path\to\g++.exe
  • Автовизначення PATH: за замовчуванням вибирається найвища підтримувана версія
  • GCC 13.3 / 14.3 / 15.2 profile
  • C++11 / C++14 / C++17 / C++20
B

Система діагностики

Формат діагностики для реальних систем збірки. Містить рядки вихідного коду, caret, include trace і warning option, а не лише рядок помилки.

  • У стилі GCC: severity / option / caret
  • -Werror, -Wno-..., -Werror=...
  • #pragma GCC diagnostic push/pop
  • #pragma GCC system_header
  • -Wsystem-headers і придушення системних заголовків
C

Макроси й семантика препроцесування

Об'єктоподібні макроси, функцієподібні макроси, порожні аргументи, варіативні макроси, перетворення на рядок, token pasting і розширення GCC для видалення ком.

  • # і ##
  • __VA_OPT__(C++20)
  • , ## __VA_ARGS__
  • defined / __has_include
  • JSON-аналіз macro trace і графа include
D

UCN і #embed

Universal character name беруть участь в ідентифікаторах і склеюванні; #embed вбудовує двійкові ресурси за семантикою GCC.

  • \uXXXX / \UXXXXXXXX
  • UCN, утворені через обернений слеш і перенесення рядка
  • # / ## зберігають написання UCN
  • #embed + limit
  • prefix / suffix / if_empty
  • gnu::offset і __has_embed
E

PCH і кеш

GCC 13/14/15 можуть використовувати стратегії PCH і кеш. Кеш не розбирає PCH GCC напряму, а перевіряє, реєструє, анулює та відстежує зовнішні .gch.

  • --pch=ignore|warn|error|report
  • Схема CMake PCH із примусовим include
  • Ізоляція шляху, версії та хешу компілятора
  • Атомарний запис, блокування каталогу, очищення за обсягом і віком
  • JSON-статистика влучань / stale / corrupt
F

Відтворювані тести

Три версії GCC, два диференціальні корпуси й реальні проєкти разом перевіряють вивід, а не лише «успішне препроцесування».

  • GCC15 / 14 / 13 — по 65/65 CTest
  • differential corpus 13/13
  • realworld corpus 3/3
  • CrucibleCpp .i → цільовий GCC → exe → запуск
  • GCC g++.dg/cpp testsuite проходить регресійне тестування
Positioning

Він замінює етап препроцесування, а не компілятор

CrucibleCpp не генерує код, не виконує оптимізацію та не розбирає двійкові PCH GCC. Він лише перетворює вихідні файли на детермінований .i, а діагностику, залежності та аналітичну інформацію передає системі збірки.
