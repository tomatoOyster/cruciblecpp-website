Почніть із першої команди

Ця сторінка охоплює встановлення, вибір цільового GCC, основні команди, PCH, діагностику та усунення неполадок. Повна реалізація й матриця тестів наведені в репозиторії GitHub.

На цій сторінці

Встановлення Швидкий старт Вибір GCC Командний рядок PCH Діагностика Усунення неполадок

Встановлення

Завантажте архів для Windows x64 і розпакуйте його в будь-який каталог. CrucibleCpp — статично скомпонована однофайлова програма, середовище виконання встановлювати не потрібно.

cruciblecpp-preprocessor.exe --version # cruciblecpp-preprocessor 3.0.1
Поточна ціль продакшну: Windows x64 + MinGW-w64 UCRT64. Підтримка інших платформ, ABI та версій GCC не гарантується.

Швидкий старт

Спочатку переконайтеся, що в PATH є цільовий g++.exe. Потім просто замініть старий g++ -E:

# Препроцесування .\cruciblecpp-preprocessor.exe -P -std=c++20 src\main.cpp -o build\main.i # Компіляція тим самим GCC g++ -std=c++20 build\main.i -o build\main.exe

Якщо цільовий GCC не додано до PATH, використайте --gcc для явного зазначення:

.\cruciblecpp-preprocessor.exe ` --gcc "D:\GCC1413\gcc14\bin\g++.exe" ` -P -std=c++20 src\main.cpp -o build\main.i

Вибір GCC

CrucibleCpp використовує попередньо визначені макроси цільового GCC, __has_* дані та шляхи пошуку include. Не використовуйте профіль GCC15 для препроцесування заголовків GCC14.

СпосібПоведінка
--gcc-version=13|14|15Знайти в PATH найвищий підтримуваний компілятор відповідної мажорної версії
--gcc <g++.exe>Використовувати вказаний компілятор, зчитуючи його версію та шляхи include
Не вказаноСканувати PATH і за замовчуванням вибирати найвищу підтримувану версію (15 → 14 → 13)
Автовизначення сканує лише PATH. Якщо компілятор встановлено в іншому каталозі, додайте його до PATH або використайте --gcc, не покладайтеся на фіксовану букву диска.

Підтримувані стандартні профілі:

-std=c++11 C++11 profile -std=c++14 C++14 profile -std=c++17 C++17 profile -std=c++20 C++20 profile

PCH

GCC-компілятор g++ -E не використовує .gch; PCH використовується лише під час справжньої компіляції. CrucibleCpp за замовчуванням читає вихідні тексти заголовків і за бажанням перевіряє, реєструє та кешує зовнішньо створені PCH.

# Попереджати, якщо знайдено .gch --pch=warn # Одразу видавати помилку, якщо знайдено .gch --pch=error # Записувати проігноровані PCH в analysis JSON --pch=report

Увімкнення кешу PCH:

.\cruciblecpp-preprocessor.exe ` --pch-cache .cache\pch ` --pch-cache-stats .cache\pch\stats.json ` -P src\main.cpp -o build\main.i

Маніфест кешу записує шлях до компілятора, версію, хеш компілятора й хеш опцій. PCH від GCC13/14/15 не плутаються між собою.

Діагностика

За замовчуванням виводяться рядки вихідного коду в стилі GCC і caret. Це можна вимкнути або налаштувати:

-fdiagnostics-color=auto|always|never -fno-diagnostics-show-caret -fno-diagnostics-show-option -Werror -Wno-error=name --max-errors 20

Підтримує #pragma GCC diagnostic push/pop/ignored/warning/error і #pragma GCC system_header. Заголовки з -isystem за замовчуванням придушують звичайні попередження, а -Wsystem-headers дозволяє знову їх показати.

Усунення неполадок

Не знайдено заголовків стандартної бібліотеки

Цільовий компілятор відсутній у PATH. Укажіть його за допомогою --gcc або додайте bin до PATH. Також можна використати -isystem для явної передачі.

Вибрано неправильну версію GCC

Використовуйте --gcc-version=13|14|15 для фіксації мажорної версії або --gcc для вказівки конкретного g++.exe. Не змішуйте цільовий профіль із заголовками іншої версії.

Кеш PCH повідомляє про corrupt

PCH не відповідає поточному компілятору/опціям або файл пошкоджено. Видаліть відповідний запис кешу й створіть PCH заново; також можна повністю вимкнути кеш PCH, щоб він читав вихідні тексти заголовків.

Вивід не компілюється GCC

Спочатку переконайтеся, що препроцесування й компіляція використовують ту саму версію GCC і -std. Потім окремо скомпілюйте .i, створений CrucibleCpp, щоб перевірити, чи проблема походить з етапу препроцесування.

CrucibleCpp — препроцесор, а не компілятор. Він не відповідає за генерацію коду, оптимізацію, компонування та розбір внутрішнього формату двійкових PCH GCC.
