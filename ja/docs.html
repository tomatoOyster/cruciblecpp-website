インストール

Windows x64 用のアーカイブをダウンロードし、任意のディレクトリに解凍するだけです。CrucibleCpp は静的リンクされた単一ファイルのプログラムで、ランタイムのインストールは不要です。

cruciblecpp-preprocessor.exe --version # cruciblecpp-preprocessor 3.0.1
現在の本番ターゲット：Windows x64 + MinGW-w64 UCRT64。その他のプラットフォーム、ABI、GCC バージョンはサポートを保証していません。

クイックスタート

まず PATH 上に目的の g++.exe があることを確認し、その後、元の g++ -E：

# プリプロセス .\cruciblecpp-preprocessor.exe -P -std=c++20 src\main.cpp -o build\main.i # 同じ GCC でコンパイル g++ -std=c++20 build\main.i -o build\main.exe

対象 GCC を PATH に追加していない場合は --gcc で明示的に指定します：

.\cruciblecpp-preprocessor.exe ` --gcc "D:\GCC1413\gcc14\bin\g++.exe" ` -P -std=c++20 src\main.cpp -o build\main.i

GCC の選択

CrucibleCpp は対象 GCC の定義済みマクロ、__has_* データ、include 検索パスを使用します。GCC15 のプロファイルで GCC14 のヘッダーをプリプロセスしないでください。

方法動作
--gcc-version=13|14|15PATH 内でメジャーバージョンが一致する最も新しい対応コンパイラを探す
--gcc <g++.exe>指定したコンパイラを直接使用し、そのバージョンと include パスを読み取る
指定なしPATH をスキャンし、デフォルトで最も新しい対応バージョンを選択（15 → 14 → 13）
自動検出は PATH のみをスキャンします。別のディレクトリにインストールした場合は、PATH に追加するか、または --gcc を使用し、固定のドライブ文字に依存しないでください。

対応する標準プロファイル：

-std=c++11 C++11 profile -std=c++14 C++14 profile -std=c++17 C++17 profile -std=c++20 C++20 profile

よく使うコマンドライン

オプション動作
-Pline markers を出力しない
-o <file>出力ファイル
-I <dir>include ディレクトリを追加
-isystem <dir>システムヘッダーディレクトリ
-D / -Uマクロの定義 / 解除
-include <file>強制インクルード
-MD -MF -MTMake/CMake 依存ファイルを生成
-finput-charset / -fexec-charset入力 / 実行文字セット
--embed-dir <dir>#embed 検索ディレクトリ
--analysis-json <file>include グラフ、macro trace、PCH レコードを出力

PCH

GCC の g++ -E は使いません。除外対象は .gch。PCH は実際のコンパイル時にのみ使用されます。CrucibleCpp はデフォルトでヘッダーのソースを読み取り、必要に応じて外部で生成された PCH を検証、登録、キャッシュします。

# .gch を検出したら warning を出力 --pch=warn # .gch を検出したらエラーにする --pch=error # 無視された PCH を analysis JSON に記録 --pch=report

PCH キャッシュを有効にする：

.\cruciblecpp-preprocessor.exe ` --pch-cache .cache\pch ` --pch-cache-stats .cache\pch\stats.json ` -P src\main.cpp -o build\main.i

キャッシュの manifest にはコンパイラのパス、バージョン、コンパイラのハッシュ、オプションのハッシュが記録されます。GCC13/14/15 の PCH が互いに誤ヒットすることはありません。

診断

デフォルトでは GCC 形式のソース行と caret を出力します。無効化または調整できます：

-fdiagnostics-color=auto|always|never -fno-diagnostics-show-caret -fno-diagnostics-show-option -Werror -Wno-error=name --max-errors 20

次のプラグマに対応しています： #pragma GCC diagnostic push/pop/ignored/warning/error と #pragma GCC system_header。既定では -isystem 由来のヘッダーは通常の警告を抑制し、-Wsystem-headers で再表示できます。

トラブルシューティング

標準ライブラリのヘッダーが見つからない

対象コンパイラが PATH にない場合は --gcc で指定するか、その bin ディレクトリを PATH に追加してください。または -isystem で明示的に渡すこともできます。

誤った GCC バージョンを選択した

次のいずれかを使います： --gcc-version=13|14|15 でメジャーバージョンを固定するか、 --gcc で具体的な g++.exe を指定します。target profile と別バージョンのヘッダーを混在させないでください。

PCH キャッシュが corrupt エラーを報告

PCH が現在のコンパイラ/オプションと一致しないか、ファイルが破損しています。該当するキャッシュエントリを削除して再生成してください。PCH キャッシュを無効にして、ヘッダーのソースを読ませることもできます。

出力を GCC でコンパイルできない

まず、プリプロセスとコンパイルで同じ GCC バージョンと -std を使用していることを確認します。続いて「CrucibleCpp が生成した .i」を単独でコンパイルし、問題がプリプロセス段階に由来するか確認します。

CrucibleCpp はプリプロセッサであり、コンパイラではありません。コード生成、最適化、リンク、GCC バイナリ PCH の内部フォーマット解析は担当しません。
