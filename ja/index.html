CrucibleCpp は独立した C++ プリプロセッサです。ソースファイルを読み取り、翻訳フェーズ 1–4 を実行して、GCC がそのままコンパイルを続けられる .i ファイルを出力します。

Why CrucibleCpp

もう一つのマクロ展開器ではなく、
検証可能なプリプロセス層です。

すべての正例は同じ経路を通ります：CrucibleCpp が生成した .i を、対応する GCC が exe にコンパイルし、実際に実行します。動作は GCC 15.2、14.3、13.3 を基準としています。

01

対象バージョンを明示

対象コンパイラを選択するには --gcc-version または --gcc を指定します。プロファイル、組み込みマクロ、include パスは同じターゲットから取得し、混在させません。

02

GCC 診断の整合性

ソースの caret、include trace、warning ID、-Werror、pragma diagnostic スタック、およびシステムヘッダーの警告抑制。

03

実プロジェクトで検証

nlohmann/json、fmt、spdlog を 3 つの GCC バージョンでプリプロセス、コンパイル、実行し、実際のヘッダーとマクロの組み合わせを網羅します。

04

完全な UCN

\uXXXX と \UXXXXXXXX は識別子、#、## に参加し、正当性チェックと出力の正規化は GCC と整合します。

05

#embed

バイナリ埋め込み、limit、gnu::offset、prefix、suffix、if_empty、および __has_embed。

06

PCH のバージョン分離

GCC 13 / 14 / 15 で PCH ポリシーとキャッシュを利用できます。manifest にはコンパイラのパス、バージョン、実行ファイルのハッシュが記録され、バージョンをまたいだ誤ヒットを防ぎます。

Compatibility

明確なマトリクスから始める

現在の本番ターゲットは Windows x64 + MinGW-w64 UCRT64 です。GCC のバージョンごとに独自のプロファイルとヘッダーを使用し、出力は対応する GCC で実際にコンパイルして検証します。

Test chain

「動きそう」では検証にならない

  • GCC15 / 14 / 13 の 3 スイート CTest、各 65/65
  • differential corpus 13/13：終了コード、診断、token ストリーム
  • realworld corpus 3/3：nlohmann/json、fmt、spdlog
  • 各正例は exe を生成したうえで実際に実行
  • PCH ポリシーとキャッシュが 3 バージョンすべてで検証に合格
  • GCC g++.dg/cpp testsuite は継続的に回帰テストを実行
