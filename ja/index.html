WHY CRUCIBLECPP

検証できるプリプロセス層。

すべての正例は同じ経路を通ります：CrucibleCpp が .i を生成し、対応 GCC が exe にコンパイルし、実際に実行します。

01

対象バージョンを明示

--gcc-version または --gcc で選択。プロファイル、組み込みマクロ、include パスは同じ GCC から取得します。

02

GCC 形式の診断

ソース行、caret、include trace、warning ID、-Werror、pragma diagnostic スタック。

03

実プロジェクト検証

nlohmann/json、fmt、spdlog を GCC 13/14/15 でプリプロセス、コンパイル、実行。

04

完全な UCN

\uXXXX / \UXXXXXXXX を識別子、#、## で処理し、検証と正規化を行います。

05

#embed

バイナリ埋め込み、limit、gnu::offset、prefix、suffix、if_empty、__has_embed。

06

バージョン分離 PCH

GCC 13/14/15 で PCH ポリシーとキャッシュを利用可能。manifest にコンパイラのパス、バージョン、ハッシュを記録。

COMPATIBILITY

明確なマトリクスから。

現在の対象は Windows x64 + MinGW-w64 UCRT64。GCC バージョンごとにプロファイルとヘッダーを使い分けます。

対象状態

TEST CHAIN

「動きそう」では終わらせない。

  • GCC15 / 14 / 13 各 65/65 CTest
  • differential corpus 13/13
  • realworld corpus 3/3
  • 各正例が exe を生成して実行
  • 3 バージョンで PCH ポリシーとキャッシュが通過
DOCUMENTATION

最初のコマンドから。

クイックスタート

cruciblecpp-preprocessor.exe -P ` -std=c++20 src\main.cpp -o build\main.i g++ -std=c++20 build\main.i -o build\main.exe

コンパイラを明示する場合：

cruciblecpp-preprocessor.exe ` --gcc "D:\path\to\g++.exe" ` -P src\main.cpp -o build\main.i

GCC の選択

  • --gcc-version=13|14|15
  • --gcc <g++.exe>
  • PATH を自動検出、既定は最新の対応版
  • -std=c++11|14|17|20
自動検出は PATH のみ。別の場所は --gcc で指定します。

ABOUT

もう一つのマクロ展開器ではなく、検証可能な層。

CrucibleCpp は翻訳フェーズ 1–4 を観察・テスト可能にします。コンパイラではありません：コード生成、最適化、リンク、GCC バイナリ PCH の解析は行いません。
