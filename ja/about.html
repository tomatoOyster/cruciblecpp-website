About the project

「前処理」を
検証可能な層へ

CrucibleCpp は、ある非常に具体的な問いから始まりました。ビルドシステムが独立した前処理結果を必要とするとき、 g++ -E のプロセス呼び出しに依存せず、それでもなお、信頼でき、説明可能で、回帰テスト可能な出力を得られるでしょうか？

なぜ独立したプリプロセッサなのか

前処理は「マクロを展開するだけ」に見えますが、実際のプロジェクトでは、診断、依存関係、PCH、文字コード、マクロ状態、ビルドキャッシュが交差するポイントになります。独立した層に切り出してこそ、個別に観察し、テストし、最適化できます。

CrucibleCpp の目標はコンパイラを書き直すことではなく、翻訳フェーズ 1–4 を、境界が明確で動作を比較できるコンポーネントにすることです。

設計原則

  • 動作は GCC を基準とします。 「もっともらしい」ではなく、実際の GCC と照合します。
  • 正例はすべてコンパイルして実行します。 前処理が成功しても、出力が使えるとは限りません。
  • バージョンは混在させません。 対象 GCC の profile、ヘッダー、コンパイルコマンドは一致していなければなりません。
  • 制限は隠しません。 未対応の機能は明記し、「できるはず」で検証を代用しません。
  • まず Windows x64 から。 まず 1 つのターゲットを信頼できるものにしてから、クロスプラットフォームを語ります。
