V3.0.1 다운로드
Capabilities

모든 계층을
검증 가능한 동작

타깃 버전 선택과 사전 정의 매크로, 진단에서 PCH와 실제 프로젝트까지, CrucibleCpp는 “아마 될 것”에 기대지 않고 반복 가능한 테스트 체인으로 동작합니다.

A

타깃 버전과 프로필

하나의 전처리기, 세 가지 타깃 GCC. 어떤 버전을 선택하든 그 버전의 사전 정의 매크로, __has_* 데이터, include 검색 경로를 사용합니다.

  • --gcc-version=13|14|15
  • --gcc D:\path\to\g++.exe
  • PATH 자동 감지, 기본값은 지원되는 최고 버전
  • GCC 13.3 / 14.3 / 15.2 profile
  • C++11 / C++14 / C++17 / C++20
B

진단 시스템

실제 빌드 시스템을 위한 진단 형식. 소스 줄, caret, include trace, warning option을 포함하며 단순한 오류 문자열이 아닙니다.

  • GCC 스타일 severity / option / caret
  • -Werror, -Wno-..., -Werror=...
  • #pragma GCC diagnostic push/pop
  • #pragma GCC system_header
  • -Wsystem-headers 및 시스템 헤더 경고 억제
C

매크로와 전처리 의미론

객체형 매크로, 함수형 매크로, 빈 인자, 가변 인자 매크로, 문자열화, token pasting, 그리고 GCC의 쉼표 제거 확장.

  • # 및 ##
  • __VA_OPT__(C++20)
  • , ## __VA_ARGS__
  • defined / __has_include
  • 매크로 trace와 include 그래프 분석 JSON
D

UCN과 #embed

Universal character name은 식별자와 결합에 참여하며, #embed 의 경우 GCC 의미론에 따라 바이너리 리소스를 삽입합니다.

  • \uXXXX / \UXXXXXXXX
  • 백슬래시 줄바꿈으로 형성된 UCN
  • # / ## 에서도 UCN 표기를 그대로 유지합니다
  • #embed + limit
  • prefix / suffix / if_empty
  • gnu::offset 및 __has_embed
E

PCH와 캐시

GCC 13/14/15 모두 PCH 정책과 캐시를 사용할 수 있습니다. 캐시는 GCC PCH를 직접 파싱하지 않습니다. 대신 검증·등록·무효화·추적 대상은 외부에서 생성된 .gch.

  • --pch=ignore|warn|error|report
  • 강제 include를 사용하는 CMake PCH 레이아웃
  • 컴파일러 경로, 버전, 해시 격리
  • 원자적 쓰기, 디렉터리 잠금, 용량 및 기간 기반 정리
  • 적중률 / stale / corrupt 통계 JSON
F

재현 가능한 테스트

세 가지 GCC, 두 개의 차분 코퍼스, 실제 프로젝트가 함께 출력을 검증하며, “전처리 성공”만 테스트하지 않습니다.

  • GCC15 / 14 / 13 각각 65/65 CTest
  • differential corpus 13/13
  • realworld corpus 3/3
  • CrucibleCpp .i → 타깃 GCC → exe → run
  • GCC g++.dg/cpp testsuite 회귀
Positioning

대체하는 것은 전처리 단계이지 컴파일러가 아닙니다

CrucibleCpp는 코드 생성도, 최적화도, GCC 바이너리 PCH 파싱도 하지 않습니다. 소스 파일을 결정적인 .i로 바꾸고, 진단과 의존성, 분석 가능한 정보를 빌드 시스템에 넘깁니다.
