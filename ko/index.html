Why CrucibleCpp

또 하나의 매크로 확장기가 아니라,
검증 가능한 전처리 계층입니다

모든 정상 케이스는 같은 경로를 거칩니다: CrucibleCpp가 생성한 .i를 해당 GCC가 exe로 컴파일한 뒤 실제로 실행합니다. 동작 기준은 GCC 15.2, 14.3, 13.3입니다.

01

명확한 타깃 버전

대상 컴파일러는 --gcc-version 또는 --gcc 옵션으로 지정합니다. 프로필, 내장 매크로, include 경로는 모두 같은 대상에서 오며 서로 섞이지 않습니다.

02

GCC 진단 정합성

소스 caret, include trace, warning ID, -Werror, pragma diagnostic 스택, 그리고 시스템 헤더 경고 억제.

03

실제 프로젝트 검증

nlohmann/json, fmt, spdlog를 세 가지 GCC 버전에서 전처리, 컴파일, 실행하여 실제 헤더와 매크로 조합까지 검증합니다.

04

완전한 UCN

\uXXXX 및 \UXXXXXXXX 은 식별자, #, ##; 적법성 검사와 출력 정규화는 GCC와 일치합니다.

05

#embed

바이너리 삽입, limit, gnu::offset, prefix, suffix, if_empty, 그리고 __has_embed.

06

PCH 버전 격리

GCC 13 / 14 / 15 모두에서 PCH 정책과 캐시를 사용할 수 있습니다. manifest에는 컴파일러 경로와 버전, 실행 파일 해시가 기록되어 버전이 다른 캐시를 잘못 재사용하지 않습니다.

Compatibility

명확한 매트릭스에서 시작합니다

현재 프로덕션 타깃은 Windows x64 + MinGW-w64 UCRT64로 고정되어 있습니다. GCC 버전마다 자체 프로필과 헤더를 사용하며, 출력은 해당 GCC로 실제 컴파일해 검증합니다.

Test chain

검증은 “되는 것처럼 보인다”가 아닙니다

  • GCC15 / 14 / 13 CTest 3종, 각각 65/65
  • differential corpus 13/13: 종료 코드, 진단, 토큰 스트림
  • realworld corpus 3/3: nlohmann/json, fmt, spdlog
  • 모든 정상 케이스는 exe 생성 후 실제로 실행
  • 세 버전 모두에서 PCH 정책과 캐시 통과
  • GCC g++.dg/cpp testsuite 상시 회귀 테스트
