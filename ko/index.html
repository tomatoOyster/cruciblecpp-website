결정론적으로

CrucibleCpp는 독립 C++ 전처리기입니다. 번역 단계 1–4를 수행하고 대상 GCC가 바로 컴파일할 수 있는 .i를 출력합니다.

CC BY-NC 4.0 설치 불필요 단일 exe
PowerShell — cruciblecpp
# 대상 GCC 프로필과 헤더
PS> .\cruciblecpp-preprocessor.exe --gcc-version=15 `
       -P src\main.cpp -o build\main.i

# 같은 GCC로 컴파일
PS> g++ -std=c++20 build\main.i -o build\main.exe
PS> .\build\main.exe

WHY CRUCIBLECPP

검증 가능한 전처리 계층.

모든 정상 사례는 같은 경로를 따릅니다. CrucibleCpp가 .i를 만들고, 해당 GCC가 exe로 컴파일한 뒤 실행합니다.

01

명시적 대상 버전

--gcc-version 또는 --gcc로 선택합니다. 프로필, 내장 매크로, include 경로가 같은 GCC에서 나옵니다.

02

GCC 스타일 진단

소스 caret, include trace, warning ID, -Werror, pragma diagnostic 스택.

03

실제 프로젝트 검증

nlohmann/json, fmt, spdlog를 GCC 13/14/15에서 전처리, 컴파일, 실행합니다.

04

완전한 UCN

\uXXXX, \UXXXXXXXX를 식별자, #, ##에서 처리하고 검증합니다.

05

#embed

바이너리 삽입, limit, gnu::offset, prefix, suffix, if_empty, __has_embed.

06

버전별 PCH

GCC 13/14/15에서 PCH 정책과 캐시를 사용합니다. manifest에 컴파일러 경로, 버전, 해시를 기록합니다.

호환성

명시적인 매트릭스.

현재 대상은 Windows x64 + MinGW-w64 UCRT64입니다. 각 GCC 버전은 자체 프로필과 헤더를 사용합니다.

테스트 체인

“되는 것 같다”로 끝내지 않습니다.

  • GCC15 / 14 / 13 각 65/65 CTest
  • differential corpus 13/13
  • realworld corpus 3/3
  • 모든 정상 사례가 exe를 만들고 실행
  • 세 버전에서 PCH 정책과 캐시 통과
문서

첫 명령부터.

빠른 시작

cruciblecpp-preprocessor.exe -P ` -std=c++20 src\main.cpp -o build\main.i g++ -std=c++20 build\main.i -o build\main.exe

컴파일러를 직접 지정할 수도 있습니다:

cruciblecpp-preprocessor.exe ` --gcc "D:\path\to\g++.exe" ` -P src\main.cpp -o build\main.i

GCC 선택

  • --gcc-version=13|14|15
  • --gcc <g++.exe>
  • PATH 자동 감지, 기본은 가장 높은 지원 버전
  • -std=c++11|14|17|20
자동 감지는 PATH만 검색합니다. 다른 위치는 --gcc를 사용하세요.

소개

또 하나의 매크로 확장기가 아닌 검증 가능한 계층.

CrucibleCpp는 번역 단계 1–4를 관찰하고 테스트할 수 있게 합니다. 컴파일러가 아니므로 코드 생성, 최적화, 링크, GCC 바이너리 PCH 분석을 하지 않습니다.
