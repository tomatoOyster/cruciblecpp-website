Installation

Ladda ner Windows x64-arkivet och packa upp det i valfri katalog. CrucibleCpp är ett statiskt länkat program i en enda fil, så ingen runtime behöver installeras.

cruciblecpp-preprocessor.exe --version # cruciblecpp-preprocessor 3.0.1
Aktuellt produktionsmål: Windows x64 + MinGW-w64 UCRT64. Andra plattformar, ABI:er och GCC-versioner stöds inte med garanti.

Snabbstart

Börja med att kontrollera att PATH innehåller rätt g++.exe. Ersätt sedan bara din befintliga g++ -E:

# Förbehandla .\cruciblecpp-preprocessor.exe -P -std=c++20 src\main.cpp -o build\main.i # Kompilera med samma GCC g++ -std=c++20 build\main.i -o build\main.exe

Om mål-GCC:n inte finns i PATH, använd --gcc för att ange den explicit:

.\cruciblecpp-preprocessor.exe ` --gcc "D:\GCC1413\gcc14\bin\g++.exe" ` -P -std=c++20 src\main.cpp -o build\main.i

Välj GCC

CrucibleCpp använder mål-GCC:ns fördefinierade makron,__has_* data och include-sökvägar. Använd inte en GCC 15-profil för att förbehandla GCC 14-headerfiler.

MetodBeteende
--gcc-version=13|14|15Hitta den högsta version som stöds i PATH som matchar huvudversionen
--gcc <g++.exe>Använd den angivna kompilatorn direkt och läs dess version och include-sökvägar
Ej angivetSkanna PATH och välj den högsta version som stöds som standard (15 → 14 → 13)
Automatisk detektering skannar bara PATH. Om den är installerad i en annan katalog lägger du till den i PATH, eller använder --gcc, och förlita dig inte på en fast enhetsbeteckning.

Standardprofiler som stöds:

-std=c++11 C++11 profile -std=c++14 C++14 profile -std=c++17 C++17 profile -std=c++20 C++20 profile

PCH

GCC:s g++ -E använder inte .gch; PCH används bara vid verklig kompilering. CrucibleCpp läser headerfilernas källkod som standard och kan valfritt validera, registrera och cacha externt genererade PCH:er.

# Varna när en .gch hittas --pch=warn # Ge ett fel direkt när en .gch hittas --pch=error # Registrera ignorerade PCH:er i analysis JSON --pch=report

Aktivera PCH-cache:

.\cruciblecpp-preprocessor.exe ` --pch-cache .cache\pch ` --pch-cache-stats .cache\pch\stats.json ` -P src\main.cpp -o build\main.i

Cache-manifestet registrerar kompilatorns sökväg, version, kompilatorhash och options-hash. PCH:er från GCC 13/14/15 kolliderar inte med varandra.

Diagnostik

Som standard skrivs GCC-lika källkodsrader och caret ut. Du kan stänga av eller justera detta:

-fdiagnostics-color=auto|always|never -fno-diagnostics-show-caret -fno-diagnostics-show-option -Werror -Wno-error=name --max-errors 20

Stöder #pragma GCC diagnostic push/pop/ignored/warning/error och #pragma GCC system_header. Headerfiler som inkluderas via -isystem undertrycker vanliga varningar som standard, och-Wsystem-headers kan visa dem igen.

Felsökning

Standardbibliotekets headerfiler hittades inte

Målkompilatorn finns inte i PATH. Använd --gcc eller lägg till sökvägen till bin i PATH. Du kan också använda -isystem för att skicka in den explicit.

Fel GCC-version har valts

Använd --gcc-version=13|14|15 för att låsa huvudversionen, eller använd --gcc för att peka ut en specifik g++.exe. Blanda inte en målprofil med headerfiler från en annan version.

PCH-cachen rapporterar corrupt

PCH:en matchar inte den aktuella kompilatorn/alternativen, eller så är filen skadad. Ta bort motsvarande cachepost och generera om den; du kan också stänga av PCH-cachen helt och låta den läsa headerfilernas källkod.

GCC kan inte kompilera utdata

Kontrollera först att förbehandlingen och kompileringen använder samma GCC-version och -std. Kompilera sedan “.i” som CrucibleCpp genererade separat för att kontrollera om problemet kommer från förbehandlingsfasen.

CrucibleCpp är en förprocessor, inte en kompilator. Den hanterar inte kodgenerering, optimering, länkning eller parsning av GCC:s interna binära PCH-format.
