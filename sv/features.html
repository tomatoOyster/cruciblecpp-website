Capabilities

Gör varje lager till
verifierbara beteenden

Från val av målversion och fördefinierade makron till diagnostik, PCH och riktiga projekt bygger CrucibleCpp inte på “det borde fungera” utan på en repeterbar kedja av tester.

A

Målversion och profil

En förprocessor, tre mål-GCC-versioner. Vilken version du än väljer får du den versionens fördefinierade makron,__has_* data och include-sökvägar.

  • --gcc-version=13|14|15
  • --gcc D:\path\to\g++.exe
  • Automatisk PATH-detektering som standard väljer den högsta version som stöds
  • GCC 13.3 / 14.3 / 15.2 profile
  • C++11 / C++14 / C++17 / C++20
B

Diagnostiksystem

Ett diagnostikformat byggt för riktiga byggsystem. Det innehåller källkodsrad, caret, include-spår och warning option – inte bara en felsträng.

  • GCC-liknande severity / option / caret
  • -Werror, -Wno-..., -Werror=...
  • #pragma GCC diagnostic push/pop
  • #pragma GCC system_header
  • -Wsystem-headers och undertryckning av systemheaderfiler
C

Makron och förbehandlingssemantik

Objektmakron, funktionsmakron, tomma argument, variadiska makron, stringifiering, token pasting och GCC:s kommaelimineringstillägg.

  • # och ##
  • __VA_OPT__(C++20)
  • , ## __VA_ARGS__
  • defined / __has_include
  • JSON för makrospår och include-grafanalys
D

UCN och #embed

Universal character names deltar i identifierare och sammanfogning;#embed Bäddar in binära resurser enligt GCC:s semantik.

  • \uXXXX / \UXXXXXXXX
  • UCN som bildas av backslash-radbrytning
  • # / ## bevarar UCN-stavning i
  • #embed + limit
  • prefix / suffix / if_empty
  • gnu::offset och __has_embed
E

PCH och cache

PCH-strategi och cache kan användas med GCC 13/14/15. Cachen parsar inte GCC:s PCH direkt, utan validerar, registrerar, invaliderar och spårar externa .gch.

  • --pch=ignore|warn|error|report
  • CMake PCH-layout med tvingade includes
  • isolering av kompilatorsökväg, version och hash
  • Atomiska skrivningar, katalogslås, rensning baserad på kapacitet och ålder
  • JSON-statistik för hit rate / stale / corrupt
F

Reproducerbara tester

Tre GCC-verktygskedjor, två differentialkorpusar och riktiga projekt validerar utdata tillsammans – inte bara att “förbehandlingen lyckades”.

  • GCC 15 / 14 / 13: 65/65 CTest vardera
  • differential corpus 13/13
  • realworld corpus 3/3
  • CrucibleCpp .i → mål-GCC → exe → kör
  • GCC g++.dg/cpp testsviteregression
Positioning

Den ersätter förbehandlingssteget, inte kompilatorn

CrucibleCpp genererar ingen kod, optimerar inget och parsar inte GCC:s binära PCH. Dess enda uppgift är att göra källfiler till deterministiska .i, och lämnar diagnostik, beroenden och analyserbar information till byggsystemet.
