تنزيل V3.0.1
Capabilities

اجعل كل طبقة
سلوكًا قابلًا للتحقق

من اختيار الإصدار الهدف ووحدات الماكرو المحددة مسبقًا والتشخيصات، إلى PCH والمشاريع الحقيقية، لا يعتمد CrucibleCpp على «يُفترض أن يعمل»، بل على سلسلة اختبارات قابلة للتكرار.

A

الإصدار الهدف وprofile

معالج مسبق واحد، وثلاثة إصدارات GCC هدف. وأي إصدار تختار، تستخدم وحدات الماكرو المحددة مسبقًا وبيانات__has_* ومسارات بحث include الخاصة به.

  • --gcc-version=13|14|15
  • --gcc D:\path\to\g++.exe
  • كشف تلقائي في PATH، مع اختيار أعلى إصدار مدعوم افتراضيًا
  • GCC 13.3 / 14.3 / 15.2 profile
  • C++11 / C++14 / C++17 / C++20
B

نظام التشخيص

تنسيق تشخيصات موجّه لأنظمة البناء الحقيقية. يتضمن سطر المصدر وcaret وinclude trace وwarning option، وليس مجرد سلسلة خطأ.

  • severity / option / caret بأسلوب GCC
  • -Werror, -Wno-..., -Werror=...
  • #pragma GCC diagnostic push/pop
  • #pragma GCC system_header
  • -Wsystem-headers وكبت رؤوس النظام
C

الماكرو ودلالات المعالجة المسبقة

ماكرو الكائنات، وماكرو الدوال، والوسائط الفارغة، وماكرو الوسائط المتغيرة، والسترنة، وtoken pasting، بالإضافة إلى امتداد إزالة الفواصل في GCC.

  • # و ##
  • __VA_OPT__(C++20)
  • , ## __VA_ARGS__
  • defined / __has_include
  • JSON لتحليل macro trace ومخطط include
D

UCN و#embed

تشارك أسماء الأحرف العالمية (Universal character name، UCN) في المعرّفات والدمج؛#embed يضمّن الموارد الثنائية وفق دلالات GCC.

  • \uXXXX / \UXXXXXXXX
  • UCN المتكوّن من فاصل السطر بالشرطة العكسية
  • # / ## مع الاحتفاظ بكتابة UCN
  • #embed + limit
  • prefix / suffix / if_empty
  • gnu::offset و __has_embed
E

PCH والتخزين المؤقت

يمكن لـ GCC 13/14/15 استخدام سياسات PCH والتخزين المؤقت. ولا يحلّل التخزين المؤقت ملفات PCH الخاصة بـ GCC مباشرة، بل يتحقق ويسجّل ويُبطل ويتتبّع ملفات PCH الخارجية الممتدة بـ .gch.

  • --pch=ignore|warn|error|report
  • تخطيط PCH في CMake للتضمين الإجباري (include)
  • عزل مسار compiler وإصداره وhash
  • كتابة ذرّية، وأقفال أدلة، وتنظيف السعة والعمر
  • إحصاءات JSON لنسبة الإصابة / stale / corrupt
F

اختبارات قابلة للتكرار

ثلاث مجموعات GCC، ومجموعتا اختبار تفاضليتان، ومشاريع حقيقية تتحقق من المخرجات معًا، لا مجرد اختبار «نجاح المعالجة المسبقة».

  • GCC15 / 14 / 13، لكل منها 65/65 CTest
  • differential corpus 13/13
  • realworld corpus 3/3
  • CrucibleCpp .i → GCC الهدف → exe → run
  • GCC g++.dg/cpp اختبارات testsuite الانحدارية
Positioning

إنه يستبدل خطوة المعالجة المسبقة، لا المترجم

لا يقوم CrucibleCpp بتوليد الشيفرة، ولا بالتحسين، ولا بتحليل ملفات PCH الثنائية الخاصة بـ GCC. وهو مسؤول فقط عن تحويل ملفات المصدر إلى ملفات .i، ويسلّم التشخيصات والتبعيات والمعلومات القابلة للتحليل إلى نظام البناء.
