اجعل المعالجة المسبقة حتمية

CrucibleCpp معالج C++ مستقل. ينفذ مراحل الترجمة 1–4 وينتج ملف .i يمكن لمترجم GCC الهدف ترجمته مباشرة.

PowerShell — cruciblecpp
# ملف تعريف GCC الهدف وترويساته
PS> .\cruciblecpp-preprocessor.exe --gcc-version=15 `
       -P src\main.cpp -o build\main.i

# الترجمة بنفس GCC
PS> g++ -std=c++20 build\main.i -o build\main.exe
PS> .\build\main.exe

لماذا

طبقة معالجة قابلة للتحقق.

كل حالة إيجابية تمر بالمسار نفسه: ينشئ CrucibleCpp ملف .i، ويترجمه GCC المطابق إلى exe، ثم يتم تشغيله.

01

إصدار هدف صريح

اختر باستخدام --gcc-version أو --gcc. الملف التعريفي والماكروهات ومسارات include تأتي من المترجم نفسه.

02

تشخيص بأسلوب GCC

سطر المصدر، caret، include trace، warning ID، -Werror ومكدس pragma diagnostic.

03

مشاريع حقيقية

يتم اختبار nlohmann/json وfmt وspdlog مع GCC 13/14/15 وترجمتها وتشغيلها.

04

دعم UCN كامل

\uXXXX و\UXXXXXXXX في المعرفات و# و## مع التحقق والتطبيع.

05

#embed

تضمين ثنائي، limit، gnu::offset، prefix، suffix، if_empty و__has_embed.

06

PCH معزول بالإصدار

PCH متاح مع GCC 13/14/15، ويسجل manifest مسار المترجم وإصداره وبصمته.

التوثيق

من الأمر الأول.

بدء سريع

cruciblecpp-preprocessor.exe -P ` -std=c++20 src\main.cpp -o build\main.i g++ -std=c++20 build\main.i -o build\main.exe

أو حدد المترجم صراحة:

cruciblecpp-preprocessor.exe ` --gcc "D:\path\to\g++.exe" ` -P src\main.cpp -o build\main.i

اختيار GCC

  • --gcc-version=13|14|15
  • --gcc <g++.exe>
  • كشف تلقائي في PATH، الافتراضي أحدث إصدار
  • -std=c++11|14|17|20
الكشف التلقائي يفحص PATH فقط؛ استخدم --gcc لمسار آخر.
