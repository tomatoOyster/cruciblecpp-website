Installation

Download Windows x64-arkivet, og udpak det til en vilkårlig mappe. CrucibleCpp er et statisk linket program i én fil, og der kræves ingen runtime-installation.

cruciblecpp-preprocessor.exe --version # cruciblecpp-preprocessor 3.0.1
Nuværende produktionsmål: Windows x64 + MinGW-w64 UCRT64. Andre platforme, ABI'er og GCC-versioner er ikke garanteret understøttet.

Hurtig start

Kontrollér først, at målet kan findes i PATH g++.exe. Erstat derefter direkte den oprindelige g++ -E:

# Præprocessér .\cruciblecpp-preprocessor.exe -P -std=c++20 src\main.cpp -o build\main.i # Kompilér med samme GCC g++ -std=c++20 build\main.i -o build\main.exe

Hvis mål-GCC'en ikke er lagt i PATH, brug --gcc Angiv eksplicit:

.\cruciblecpp-preprocessor.exe ` --gcc "D:\GCC1413\gcc14\bin\g++.exe" ` -P -std=c++20 src\main.cpp -o build\main.i

Vælg GCC

CrucibleCpp bruger mål-GCC'ens indbyggede makroer,__has_* data og include-søgestier. Brug ikke GCC15's profil til at præprocessere GCC14's header-filer.

MådeAdfærd
--gcc-version=13|14|15Søger i PATH efter den højest understøttede compiler med matchende hovedversion
--gcc <g++.exe>Brug den angivne compiler direkte, og læs dens version og include-stier
Hvis du ikke angiverScanner PATH og vælger som standard den højest understøttede version (15 → 14 → 13)
Automatisk detektering scanner kun PATH. Hvis den er installeret i en anden mappe, skal du føje den til PATH eller bruge --gcc, og undgå at stole på faste drevbogstaver.

Understøttede standardprofiler:

-std=c++11 C++11 profile -std=c++14 C++14 profile -std=c++17 C++17 profile -std=c++20 C++20 profile

PCH

GCC's g++ -E bruger ikke .gch; PCH bruges kun ved den egentlige kompilering. CrucibleCpp læser som standard header-kildekoden og kan valgfrit validere, registrere og cache eksternt genererede PCH'er.

# Giv en advarsel, når der findes en .gch --pch=warn # Rapportér fejl, når der findes en .gch --pch=error # Registrér ignorerede PCH'er i analysis-JSON --pch=report

Aktivér PCH-cache:

.\cruciblecpp-preprocessor.exe ` --pch-cache .cache\pch ` --pch-cache-stats .cache\pch\stats.json ` -P src\main.cpp -o build\main.i

Cache-manifestet registrerer compilersti, version, compiler-hash og hash for optioner. PCH'er fra GCC13/14/15 rammer ikke hinanden ved en fejl.

Diagnostik

Som standard udsendes GCC-stil kildekodelinjer og caret. Det kan slås fra eller justeres:

-fdiagnostics-color=auto|always|never -fno-diagnostics-show-caret -fno-diagnostics-show-option -Werror -Wno-error=name --max-errors 20

Understøtter #pragma GCC diagnostic push/pop/ignored/warning/error og #pragma GCC system_header. Fra -isystem header-filer undertrykker som standard almindelige advarsler,-Wsystem-headers kan vises igen.

Fejlfinding

Kan ikke finde standardbibliotekets header-filer

Målkompileren er ikke i PATH. Brug --gcc angiver, eller tilføj dens bin -mappen til PATH. Du kan også bruge -isystem sendes eksplicit.

Forkert GCC-version valgt

Med --gcc-version=13|14|15 låser hovedversionen, eller brug --gcc peger på en bestemt g++.exe. Bland ikke en targetprofil med header-filer fra en anden version.

PCH-cachen rapporterer corrupt

PCH'en matcher ikke den aktuelle compiler/optioner, eller filen er beskadiget. Slet den pågældende cachepost, og generér den igen; du kan også slå PCH-cachen fra, så header-kildekoden læses i stedet.

Outputtet kan ikke kompileres af GCC

Kontrollér først, at præprocessering og kompilering bruger samme GCC-version og -std. Kompilér derefter “den .i-fil, som CrucibleCpp genererede” separat for at afgøre, om problemet stammer fra præprocesseringen.

CrucibleCpp er en præprocessor, ikke en compiler. Den håndterer ikke kodegenerering, optimering, linkning eller parsing af det interne format i GCC's binære PCH-filer.
