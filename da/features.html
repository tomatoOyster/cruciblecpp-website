Verificerbar adfærd

Fra valg af målversion og indbyggede makroer over diagnostik til PCH og rigtige projekter fungerer CrucibleCpp ikke ud fra “det burde virke”, men ud fra en reproducerbar testkæde.

A

Målversion og profil

Én præprocessor, tre mål-GCC'er. Den version, du vælger, bestemmer de indbyggede makroer,__has_* data og include-søgestier.

  • --gcc-version=13|14|15
  • --gcc D:\path\to\g++.exe
  • Automatisk PATH-detektering, vælger som standard den højest understøttede version
  • GCC 13.3 / 14.3 / 15.2 profile
  • C++11 / C++14 / C++17 / C++20
B

Diagnostiksystem

Diagnostikformat til rigtige buildsystemer. Indeholder kildekodelinje, caret, include trace og warning option — ikke bare en fejlstreng.

  • GCC-stil severity / option / caret
  • -Werror, -Wno-..., -Werror=...
  • #pragma GCC diagnostic push/pop
  • #pragma GCC system_header
  • -Wsystem-headers og undertrykkelse af systemheadere
C

Makroer og præprocesseringssemantik

Objektmakroer, funktionsmakroer, tomme argumenter, variadiske makroer, stringification, token pasting og GCC's kommuelimineringsudvidelse.

  • # og ##
  • __VA_OPT__(C++20)
  • , ## __VA_ARGS__
  • defined / __has_include
  • macro trace og include-grafanalyse i JSON
D

UCN og #embed

Universal character name indgår i identifikatorer og sammensætning;#embed Indlejrer binære ressourcer efter GCC-semantik.

  • \uXXXX / \UXXXXXXXX
  • UCN dannet af backslash-linjefortsættelse
  • # / ## bevarer UCN-stavemåden
  • #embed + limit
  • prefix / suffix / if_empty
  • gnu::offset og __has_embed
E

PCH og cache

GCC 13/14/15 kan alle bruge PCH-strategi og cache. Cachen parser ikke GCC-PCH direkte, men validerer, registrerer, invaliderer og sporer eksterne .gch.

  • --pch=ignore|warn|error|report
  • CMake-PCH-layout med gennemtvinget include
  • compilersti, version og hash isoleres
  • Atomare skrivninger, mappelås, kapacitets- og aldersoprydning
  • hitrate / stale / corrupt-statistik i JSON
F

Reproducerbare tests

Tre GCC-sæt, to differential-korpus og rigtige projekter validerer outputtet sammen — der testes ikke kun “præprocessering lykkedes”.

  • GCC15 / 14 / 13, hver med 65/65 CTest
  • differential corpus 13/13
  • realworld corpus 3/3
  • CrucibleCpp .i → mål-GCC → exe → run
  • GCC g++.dg/cpp testsuite-regression
Positioning

Den erstatter præprocesseringstrinnet, ikke compileren

CrucibleCpp udfører ikke kodegenerering, optimering eller parsing af binære GCC-PCH'er. Den sørger kun for at gøre kildefiler til deterministiske .i, og giver diagnostik, afhængigheder og analyserbar information videre til buildsystemet.
