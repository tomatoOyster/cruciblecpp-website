Установка

Скачайте архив для Windows x64 и распакуйте его в любой каталог. CrucibleCpp — статически слинкованная программа в одном файле, устанавливать среду выполнения не нужно.

cruciblecpp-preprocessor.exe --version # cruciblecpp-preprocessor 3.0.1
Текущая производственная цель: Windows x64 + MinGW-w64 UCRT64. Поддержка других платформ, ABI и версий GCC не гарантируется.

Быстрый старт

Сначала убедитесь, что в PATH находится целевой g++.exe. Затем просто замените прежний g++ -E:

# Препроцессирование .\cruciblecpp-preprocessor.exe -P -std=c++20 src\main.cpp -o build\main.i # Компиляция тем же GCC g++ -std=c++20 build\main.i -o build\main.exe

Если целевой GCC не добавлен в PATH, используйте --gcc для явного указания:

.\cruciblecpp-preprocessor.exe ` --gcc "D:\GCC1413\gcc14\bin\g++.exe" ` -P -std=c++20 src\main.cpp -o build\main.i

Выбор GCC

CrucibleCpp использует предопределённые макросы целевого GCC, данные __has_* и пути поиска include. Не используйте профиль GCC15 для препроцессирования заголовков GCC14.

СпособПоведение
--gcc-version=13|14|15Найти в PATH максимальный поддерживаемый компилятор с нужной мажорной версией
--gcc <g++.exe>Использовать указанный компилятор, читая его версию и пути include
Не указаноСканировать PATH и по умолчанию выбирать максимальную поддерживаемую версию (15 → 14 → 13)
Автоопределение сканирует только PATH. Если компилятор установлен в другом каталоге, добавьте его в PATH или используйте --gcc, а не полагайтесь на фиксированную букву диска.

Поддерживаемые стандартные профили:

-std=c++11 C++11 profile -std=c++14 C++14 profile -std=c++17 C++17 profile -std=c++20 C++20 profile

PCH

GCC-компилятор g++ -E не использует .gch; PCH используется только при реальной компиляции. По умолчанию CrucibleCpp читает исходный код заголовков и при необходимости проверяет, регистрирует и кэширует PCH, созданные извне.

# Обнаружив .gch, выводить предупреждение --pch=warn # Обнаружив .gch, сразу выдавать ошибку --pch=error # Записывать проигнорированные PCH в analysis JSON --pch=report

Включение кэша PCH:

.\cruciblecpp-preprocessor.exe ` --pch-cache .cache\pch ` --pch-cache-stats .cache\pch\stats.json ` -P src\main.cpp -o build\main.i

Манифест кэша записывает путь к компилятору, его версию, хеш компилятора и хеш опций. PCH от GCC13/14/15 не путаются между собой.

Диагностика

По умолчанию выводятся строки исходника и caret в стиле GCC. Это можно отключить или настроить:

-fdiagnostics-color=auto|always|never -fno-diagnostics-show-caret -fno-diagnostics-show-option -Werror -Wno-error=name --max-errors 20

Поддерживается #pragma GCC diagnostic push/pop/ignored/warning/error и #pragma GCC system_header. Заголовки из -isystem по умолчанию подавляют обычные предупреждения, а -Wsystem-headers позволяет снова их показать.

Устранение неполадок

Не найдены заголовки стандартной библиотеки

Целевой компилятор отсутствует в PATH. Используйте --gcc для указания компилятора, или добавьте его bin в PATH. Также можно использовать -isystem для явной передачи.

Выбрана неверная версия GCC

Используйте --gcc-version=13|14|15 для фиксации мажорной версии, или укажите с помощью --gcc конкретный g++.exe. Не смешивайте целевой профиль с заголовками другой версии.

Кэш PCH сообщает corrupt

PCH не соответствует текущему компилятору/опциям или файл повреждён. Удалите соответствующую запись кэша и создайте PCH заново; можно также полностью отключить кэш PCH, чтобы читались исходники заголовков.

Вывод не компилируется GCC

Сначала убедитесь, что препроцессирование и компиляция используют одну и ту же версию GCC и -std. Затем отдельно скомпилируйте «.i, созданный CrucibleCpp», чтобы проверить, не связана ли проблема с этапом препроцессирования.

CrucibleCpp — препроцессор, а не компилятор. Он не отвечает за генерацию кода, оптимизацию, компоновку и разбор внутреннего формата двоичных PCH GCC.
