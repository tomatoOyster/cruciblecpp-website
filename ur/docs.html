پہلی کمانڈ سے آغاز کریں

یہ صفحہ انسٹالیشن، ہدف GCC کے انتخاب، عام کمانڈ لائن، PCH، تشخیص اور مسئلہ حل کرنے کو محیط ہے۔ مکمل امپلیمنٹیشن اور ٹیسٹ میٹرکس کے لیے GitHub ریپوزٹری دیکھیں۔

اس صفحے کے مندرجات

انسٹالیشن فوری آغاز GCC کا انتخاب کمانڈ لائن PCH تشخیص مسئلہ حل کرنا

انسٹالیشن

Windows x64 کا آرکائیو ڈاؤن لوڈ کریں اور کسی بھی ڈائریکٹری میں ایکسٹریکٹ کر لیں۔ CrucibleCpp اسٹیٹک لنک شدہ سنگل فائل پروگرام ہے، اسے رن ٹائم انسٹال کرنے کی ضرورت نہیں۔

cruciblecpp-preprocessor.exe --version # cruciblecpp-preprocessor 3.0.1
موجودہ پروڈکشن ہدف: Windows x64 + MinGW-w64 UCRT64۔ دیگر پلیٹ فارمز، ABI اور GCC ورژنز کے لیے سپورٹ کا وعدہ نہیں ہے۔

فوری آغاز

پہلے PATH میں ہدف کا پتہ لگائیں: g++.exe۔ پھر براہِ راست پرانے g++ -E:

# پیش پردازش .\cruciblecpp-preprocessor.exe -P -std=c++20 src\main.cpp -o build\main.i # اسی GCC سے کمپائل کریں g++ -std=c++20 build\main.i -o build\main.exe

اگر ہدف GCC کو PATH میں نہیں رکھا، تو --gcc سے واضح طور پر بتائیں:

.\cruciblecpp-preprocessor.exe ` --gcc "D:\GCC1413\gcc14\bin\g++.exe" ` -P -std=c++20 src\main.cpp -o build\main.i

GCC کا انتخاب

CrucibleCpp ہدف GCC کے پیش طے شدہ میکرو،__has_* ڈیٹا اور include کے تلاش کے راستے استعمال کرتا ہے۔ GCC15 کا پروفائل GCC14 کے ہیڈرز کی پیش پردازش کے لیے استعمال نہ کریں۔

طریقہرویہ
--gcc-version=13|14|15PATH میں مماثل بڑے ورژن والا سب سے زیادہ معاون کمپائلر تلاش کرتا ہے
--gcc <g++.exe>مخصوص کمپائلر کو براہِ راست استعمال کرتا ہے اور اس کا ورژن اور include کا راستہ پڑھتا ہے
غیر متعینPATH اسکین کرتا ہے، بطورِ ڈیفالٹ سب سے زیادہ معاون ورژن منتخب کرتا ہے (15 → 14 → 13)
خودکار جانچ صرف PATH اسکین کرتی ہے۔ اگر انسٹالیشن کسی اور ڈائریکٹری میں ہے تو اسے PATH میں شامل کریں، یا --gccکا استعمال کریں، اور کسی مقررہ ڈرائیو لیٹر پر انحصار نہ کریں۔

معاون معیاری پروفائلز:

-std=c++11 C++11 profile -std=c++14 C++14 profile -std=c++17 C++17 profile -std=c++20 C++20 profile

عام کمانڈ لائن

پیرامیٹرکام
-Pline markers آؤٹ پٹ نہیں کرتا
-o <file>آؤٹ پٹ فائل
-I <dir>include ڈائریکٹری شامل کرتا ہے
-isystem <dir>سسٹم ہیڈر ڈائریکٹری
-D / -Uمیکرو متعین / غیر متعین کریں
-include <file>لازمی include
-MD -MF -MTMake/CMake ڈیپنڈنسی فائل بناتا ہے
-finput-charset / -fexec-charsetان پٹ / ایگزیکیوشن کریکٹر سیٹ
--embed-dir <dir>#embed تلاش کی ڈائریکٹری
--analysis-json <file>include گراف، میکرو trace اور PCH ریکارڈ آؤٹ پٹ کرتا ہے

PCH

GCC کا g++ -E کمانڈ .gch فائلوں کو استعمال نہیں کرتا؛ PCH صرف اصل کمپائل کے وقت استعمال ہوتا ہے۔ CrucibleCpp بطورِ ڈیفالٹ ہیڈر فائلوں کا سورس پڑھتا ہے اور اختیاری طور پر بیرونی طور پر بنائے گئے PCH کی تصدیق، رجسٹریشن اور کیشنگ کرتا ہے۔

# .gch ملنے پر وارننگ دکھائیں --pch=warn # .gch ملنے پر براہِ راست ایرر دیں --pch=error # analysis JSON میں نظر انداز شدہ PCH درج کریں --pch=report

PCH کیش فعال کریں:

.\cruciblecpp-preprocessor.exe ` --pch-cache .cache\pch ` --pch-cache-stats .cache\pch\stats.json ` -P src\main.cpp -o build\main.i

کیش manifest کمپائلر کا پاتھ، ورژن، کمپائلر ہیش اور آپشنز کا hash ریکارڈ کرتا ہے۔ GCC13/14/15 کے PCH ایک دوسرے سے غلط طریقے سے نہیں ٹکراتے۔

تشخیص

بطورِ ڈیفالٹ GCC طرز کی سورس لائن اور caret آؤٹ پٹ ہوتے ہیں۔ انہیں بند یا ایڈجسٹ کیا جا سکتا ہے:

-fdiagnostics-color=auto|always|never -fno-diagnostics-show-caret -fno-diagnostics-show-option -Werror -Wno-error=name --max-errors 20

سپورٹ کرتا ہے #pragma GCC diagnostic push/pop/ignored/warning/error اور #pragma GCC system_header۔ -isystem سے آنے والے ہیڈرز میں عام انتباہات بطورِ ڈیفالٹ دبا دیے جاتے ہیں،-Wsystem-headers انہیں دوبارہ دکھا سکتا ہے۔

مسئلہ حل کرنا

اسٹینڈرڈ لائبریری کے ہیڈر نہیں مل رہے

ہدف کمپائلر PATH میں نہیں ہے۔ --gcc سے واضح کریں، یا اس کی bin ڈائریکٹری PATH میں شامل کریں۔ آپ -isystem سے واضح طور پر پاس کر سکتے ہیں۔

غلط GCC ورژن منتخب ہو گیا

بڑا ورژن مقرر کرنے کے لیے --gcc-version=13|14|15 کا استعمال کریں، یا --gcc سے مخصوص g++.exe کی طرف اشارہ کریں۔ target profile کو کسی دوسرے ورژن کے ہیڈرز کے ساتھ مکس نہ کریں۔

PCH کیش corrupt کی رپورٹ دیتا ہے

PCH موجودہ کمپائلر/آپشنز سے مماثل نہیں ہے، یا فائل خراب ہے۔ متعلقہ کیش اندراج حذف کر کے دوبارہ بنائیں؛ آپ PCH کیش بند بھی کر سکتے ہیں تاکہ یہ ہیڈر فائلوں کا سورس پڑھے۔

آؤٹ پٹ GCC سے کمپائل نہیں ہوتا

پہلے یقینی بنائیں کہ پیش پردازش اور کمپائلیشن میں ایک ہی GCC ورژن اور ایک ہی -std۔ پھر «CrucibleCpp سے بنی .i» کو الگ سے کمپائل کریں تاکہ معلوم ہو کہ مسئلہ پیش پردازش کے مرحلے سے ہے یا نہیں۔

CrucibleCpp پیش پردازند ہے، کمپائلر نہیں۔ یہ کوڈ جنریشن، آپٹیمائزیشن، لنکنگ اور GCC کے بائنری PCH کے اندرونی فارمیٹ کی پارسنگ کا ذمہ دار نہیں ہے۔
