Capabilities

ہر تہہ کو
قابلِ تصدیق رویّہ بنائیں

ہدف ورژن کے انتخاب، پیش طے شدہ میکرو، تشخیص سے لے کر PCH اور حقیقی پروجیکٹس تک، CrucibleCpp «شاید چل جائے» پر نہیں، بلکہ قابلِ تکرار ٹیسٹ زنجیر پر چلتا ہے۔

A

ہدف ورژن اور پروفائل

ایک پیش پردازند، تین ہدف GCC۔ جو ورژن منتخب کریں، اسی ورژن کے پیش طے شدہ میکرو،__has_* ڈیٹا اور include کے تلاش کے راستے استعمال کرتا ہے۔

  • --gcc-version=13|14|15
  • --gcc D:\path\to\g++.exe
  • PATH کی خودکار جانچ، بطورِ ڈیفالٹ سب سے زیادہ معاون ورژن منتخب ہوتا ہے
  • GCC 13.3 / 14.3 / 15.2 profile
  • C++11 / C++14 / C++17 / C++20
B

تشخیصی نظام

حقیقی بلڈ سسٹمز کے لیے تشخیصی فارمیٹ۔ اس میں سورس لائن، caret، include trace اور warning option شامل ہیں، صرف ایک ایرر اسٹرنگ نہیں۔

  • GCC طرز کے severity / option / caret
  • -Werror, -Wno-..., -Werror=...
  • #pragma GCC diagnostic push/pop
  • #pragma GCC system_header
  • -Wsystem-headers اور سسٹم ہیڈرز میں انتباہات کی روک تھام
C

میکرو اور پیش پردازش کے سیمنٹکس

آبجیکٹ میکرو، فنکشن میکرو، خالی آرگیومنٹس، ویری ایڈک میکرو، اسٹرنگائزیشن، token pasting، اور GCC کی کوما ہٹانے کی توسیع۔

  • # اور ##
  • __VA_OPT__(C++20)
  • , ## __VA_ARGS__
  • defined / __has_include
  • macro trace اور include گراف کا تجزیہ JSON
D

UCN اور #embed

Universal character name شناخت کنندگان اور ٹوکن جوڑنے میں حصہ لیتے ہیں؛#embed GCC کے سیمنٹکس کے مطابق بائنری وسائل ایمبیڈ کرتا ہے۔

  • \uXXXX / \UXXXXXXXX
  • بیک سلیش اور نئی لائن سے بننے والا UCN
  • # / ## میں UCN کی ہجے محفوظ رہتی ہیں
  • #embed + limit
  • prefix / suffix / if_empty
  • gnu::offset اور __has_embed
E

PCH اور کیش

GCC 13/14/15 سب PCH پالیسی اور کیش استعمال کر سکتے ہیں۔ کیش GCC PCH کو براہِ راست پارس نہیں کرتا، بلکہ تصدیق، رجسٹریشن، انویلیڈیشن اور ٹریکنگ کا ہدف بیرونی .gch.

  • --pch=ignore|warn|error|report
  • include کو لازمی بنانے والا CMake PCH لے آؤٹ
  • compiler کے پاتھ، ورژن اور ہیش کی علیحدگی
  • اٹامک رائٹ، ڈائریکٹری لاک، سائز اور عمر کی بنیاد پر صفائی
  • ہٹ ریٹ / stale / corrupt اعداد و شمار JSON
F

قابلِ تکرار ٹیسٹ

تین GCC سیٹ، دو تفریقی کارپس اور حقیقی پروجیکٹس مل کر آؤٹ پٹ کی تصدیق کرتے ہیں، صرف «پیش پردازش کامیاب» کا ٹیسٹ نہیں۔

  • GCC15 / 14 / 13 میں سے ہر ایک 65/65 CTest
  • differential corpus 13/13
  • realworld corpus 3/3
  • CrucibleCpp .i → ہدف GCC → exe → run
  • GCC g++.dg/cpp testsuite ریگریشن
Positioning

یہ کمپائلر نہیں، پیش پردازش کے مرحلے کی جگہ لیتا ہے

CrucibleCpp کوڈ جنریشن نہیں کرتا، آپٹیمائزیشن نہیں کرتا اور GCC کا بائنری PCH پارس نہیں کرتا۔ یہ صرف سورس فائلوں کو ایک متعین .i میں بدل کر تشخیص، انحصارات اور قابلِ تجزیہ معلومات بلڈ سسٹم کو سونپ دیتا ہے۔
