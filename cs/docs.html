Instalace

Stáhněte archiv pro Windows x64 a rozbalte jej do libovolného adresáře. CrucibleCpp je staticky linkovaný jednosouborový program, takže není nutné instalovat žádné běhové prostředí.

cruciblecpp-preprocessor.exe --version # cruciblecpp-preprocessor 3.0.1
Aktuální produkční cíl: Windows x64 + MinGW-w64 UCRT64. Jiné platformy, ABI a verze GCC nejsou garantovány.

Rychlý start

Nejprve ověřte, že v PATH je cílový g++.exe. Potom jednoduše nahraďte původní g++ -E:

# Preprocessing .\cruciblecpp-preprocessor.exe -P -std=c++20 src\main.cpp -o build\main.i # Kompilace stejným GCC g++ -std=c++20 build\main.i -o build\main.exe

Pokud cílový GCC není v PATH, použijte --gcc a určete jej výslovně:

.\cruciblecpp-preprocessor.exe ` --gcc "D:\GCC1413\gcc14\bin\g++.exe" ` -P -std=c++20 src\main.cpp -o build\main.i

Volba GCC

CrucibleCpp používá předdefinovaná makra cílového GCC,__has_* data a cesty pro vyhledávání include. Nepoužívejte profil GCC 15 k preprocessingu hlaviček z GCC 14.

ZpůsobChování
--gcc-version=13|14|15Vyhledá v PATH nejvyšší podporovaný kompilátor odpovídající hlavní verzi
--gcc <g++.exe>Použije zadaný kompilátor přímo a načte jeho verzi a include cesty
NezadánoProhledá PATH a standardně zvolí nejvyšší podporovanou verzi (15 → 14 → 13)
Automatická detekce prohledává pouze PATH. Pokud je nainstalován jinde, přidejte jej do PATH, nebo použijte --gcc. Nespoléhejte na pevně dané písmeno disku.

Podporované standardní profily:

-std=c++11 C++11 profile -std=c++14 C++14 profile -std=c++17 C++17 profile -std=c++20 C++20 profile

PCH

Kompilátor GCC g++ -E nepoužívá .gch; PCH se používá až při skutečné kompilaci. CrucibleCpp standardně čte zdrojové texty hlaviček a volitelně validuje, eviduje a cachuje externě vytvořené PCH.

# Při nalezení .gch vypsat varování --pch=warn # Při nalezení .gch hlásit chybu --pch=error # Zaznamenat ignorované PCH do analysis JSON --pch=report

Zapnutí PCH cache:

.\cruciblecpp-preprocessor.exe ` --pch-cache .cache\pch ` --pch-cache-stats .cache\pch\stats.json ` -P src\main.cpp -o build\main.i

Manifest cache zaznamenává cestu ke kompilátoru, verzi, hash kompilátoru a hash voleb. PCH z GCC 13/14/15 se vzájemně nepletou.

Diagnostika

Standardně vypisuje zdrojové řádky a caret ve stylu GCC. Lze vypnout nebo upravit:

-fdiagnostics-color=auto|always|never -fno-diagnostics-show-caret -fno-diagnostics-show-option -Werror -Wno-error=name --max-errors 20

Podporuje #pragma GCC diagnostic push/pop/ignored/warning/error a #pragma GCC system_header. Hlavičky z -isystem ve výchozím stavu potlačují běžná varování,-Wsystem-headers je dokáže znovu zobrazit.

Řešení problémů

Nelze najít hlavičky standardní knihovny

Cílový kompilátor není v PATH. Zvolte jej pomocí --gcc nebo přidejte jeho bin adresář do PATH. Alternativně pomocí -isystem určete adresář explicitně.

Byla zvolena nesprávná verze GCC

Pomocí --gcc-version=13|14|15 pevně zvolte hlavní verzi, nebo pomocí --gcc odkazujte na konkrétní g++.exe. Nemíchejte cílový profil s hlavičkami jiné verze.

PCH cache hlásí corrupt

PCH neodpovídá aktuálnímu kompilátoru či volbám, případně je soubor poškozený. Smažte odpovídající položku cache a vygenerujte ji znovu; alternativně PCH cache zcela vypněte a nechte jej číst zdrojové texty hlaviček.

Výstup nelze zkompilovat pomocí GCC

Nejprve ověřte, že preprocessing i kompilace používají stejnou verzi GCC a -std. Potom zvlášť zkompilujte „.i vygenerované nástrojem CrucibleCpp“ a zjistěte, zda problém nepochází z fáze preprocessingu.

CrucibleCpp je preprocesor, ne kompilátor. Nestará se o generování kódu, optimalizace, linkování ani o parsování interního binárního formátu PCH GCC.
