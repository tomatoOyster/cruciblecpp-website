Capabilities

Udělejte z každé vrstvy
ověřitelné chování

Od volby cílové verze a předdefinovaných maker přes diagnostiku až po PCH a skutečné projekty: CrucibleCpp nestojí na „mělo by to fungovat“, ale na opakovatelném řetězci testů.

A

Cílová verze a profil

Jeden preprocesor, tři cílové GCC. Verze, kterou zvolíte, určuje předdefinovaná makra,__has_* data a cesty pro vyhledávání include.

  • --gcc-version=13|14|15
  • --gcc D:\path\to\g++.exe
  • Automaticky detekuje v PATH a standardně volí nejvyšší podporovanou verzi
  • GCC 13.3 / 14.3 / 15.2 profile
  • C++11 / C++14 / C++17 / C++20
B

Diagnostický systém

Diagnostický formát pro skutečné systémy sestavení. Obsahuje řádek zdrojového kódu, caret, include trace a warning option – nejde jen o řetězec s chybou.

  • GCC styl severity / option / caret
  • -Werror, -Wno-..., -Werror=...
  • #pragma GCC diagnostic push/pop
  • #pragma GCC system_header
  • -Wsystem-headers a potlačení varování systémových hlaviček
C

Makra a sémantika preprocessingu

Objektová a funkční makra, prázdné argumenty, variadická makra, stringifikace, token pasting a rozšíření GCC pro odstraňování čárek.

  • # a ##
  • __VA_OPT__(C++20)
  • , ## __VA_ARGS__
  • defined / __has_include
  • JSON s macro trace a analýzou include grafu
D

UCN a #embed

Universal character names se podílejí na identifikátorech a zřetězování;#embed vkládá binární zdroje podle sémantiky GCC.

  • \uXXXX / \UXXXXXXXX
  • UCN vzniklé zpětným lomítkem a zalomením řádku
  • # / ## zachovávají zápis UCN
  • #embed + limit
  • prefix / suffix / if_empty
  • gnu::offset a __has_embed
E

PCH a cache

GCC 13/14/15 mohou používat PCH strategie i cache. Cache neparsuje PCH GCC přímo, ale ověřuje, eviduje, invaliduje a sleduje externí .gch.

  • --pch=ignore|warn|error|report
  • rozvržení PCH v CMake s vynuceným include
  • izolace cesty, verze a hashe kompilátoru
  • atomový zápis, zámky adresářů, čištění podle kapacity a stáří
  • JSON se statistikami zásahů / stale / corrupt
F

Reprodukovatelné testy

Tři sady GCC, dva diferenciální korpusy a skutečné projekty společně ověřují výstup – nejde jen o test „preprocessing proběhl“.

  • GCC 15 / 14 / 13, každý 65/65 CTest
  • differential corpus 13/13
  • realworld corpus 3/3
  • CrucibleCpp .i → cílový GCC → exe → run
  • GCC g++.dg/cpp regrese testsuite
Positioning

Nahrazuje krok preprocessingu, ne kompilátor

CrucibleCpp negeneruje kód, neoptimalizuje a neparsuje binární PCH GCC. Pouze převádí zdrojové soubory na deterministický soubor .i a předává diagnostiku, závislosti a analyzovatelné informace systému sestavení.
