About the project

把「預處理」
變成可驗證的一層

CrucibleCpp 從一個很具體的問題開始：當建置系統需要獨立的預處理結果時，能不能不依賴 g++ -E 的行程呼叫，同時仍能得到可信、可解釋、可回歸的輸出？

為什麼是獨立預處理器

預處理看起來只是「展開巨集」，但真實專案會把它變成診斷、相依性、PCH、字元集、巨集狀態與建置快取的交叉點。把它拆成獨立層，才能單獨觀察、測試和最佳化。

CrucibleCpp 的目標不是重寫編譯器，而是把翻譯階段 1–4 做成一個邊界清晰、行為可對照的元件。

設計原則

  • 行為以 GCC 為基準。 不是「看起來合理」，而是與真實 GCC 對照。
  • 每個正例都要編譯並執行。 預處理成功不等於輸出可用。
  • 版本不混用。 目標 GCC 的 profile、標頭檔與編譯命令必須一致。
  • 不隱藏限制。 未支援的能力會明確寫出，不用「應該可以」代替驗證。
  • 先做 Windows x64。 先把一個目標做到可信，再談跨平台。
