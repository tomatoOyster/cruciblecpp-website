WHY CRUCIBLECPP

可驗證的預處理層。

每個正例都經過：CrucibleCpp 產生 .i，對應 GCC 編譯成 exe，再實際執行。

01

明確的目標版本

用 --gcc-version 或 --gcc 選擇。profile、內建巨集與 include 路徑都來自同一個 GCC。

02

GCC 風格診斷

原始碼 caret、include trace、warning ID、-Werror、pragma diagnostic 堆疊與系統標頭抑制。

03

真實專案驗證

nlohmann/json、fmt、spdlog 在 GCC 13/14/15 上完成預處理、編譯與執行。

04

完整 UCN

\uXXXX / \UXXXXXXXX 參與識別字、#、##，含合法性檢查與正規化輸出。

05

#embed

二進位嵌入、limit、gnu::offset、prefix、suffix、if_empty 與 __has_embed。

06

版本隔離的 PCH

GCC 13/14/15 的 PCH 策略與快取可用；manifest 記錄編譯器路徑、版本與執行檔雜湊。

COMPATIBILITY

從明確的矩陣開始。

目前生產目標為 Windows x64 + MinGW-w64 UCRT64。各 GCC 版本使用自己的 profile 與標頭檔。

DOCUMENTATION

從第一條指令開始。

快速開始

cruciblecpp-preprocessor.exe -P ` -std=c++20 src\main.cpp -o build\main.i g++ -std=c++20 build\main.i -o build\main.exe

也可明確指定：

cruciblecpp-preprocessor.exe ` --gcc "D:\path\to\g++.exe" ` -P src\main.cpp -o build\main.i

選擇 GCC

  • --gcc-version=13|14|15
  • --gcc <g++.exe>
  • PATH 自動偵測，預設最高版本
  • -std=c++11|14|17|20
自動偵測只掃描 PATH；其他位置請用 --gcc。

ABOUT

可驗證的一層，而不是另一個巨集展開器。

CrucibleCpp 讓翻譯階段 1–4 可觀察、可測試。它不是編譯器：不負責程式碼產生、最佳化、連結或 GCC 二進位 PCH 解析。
