Capabilities

把每一層都做成
可驗證的行為

從目標版本選擇、預定義巨集、診斷，到 PCH 和真實專案，CrucibleCpp 不靠「應該可以」運作，而是靠可重複的測試鏈路。

A

目標版本與 profile

一套預處理器，三種目標 GCC。選擇哪個版本，就使用哪個版本的預定義巨集、__has_* 資料和 include 搜尋路徑。

  • --gcc-version=13|14|15
  • --gcc D:\path\to\g++.exe
  • PATH 自動偵測，預設選擇最高支援版本
  • GCC 13.3 / 14.3 / 15.2 profile
  • C++11 / C++14 / C++17 / C++20
B

診斷系統

為真實建置系統設計的診斷格式。包含原始碼行、caret、include trace 和 warning option，不只是一條錯誤字串。

  • GCC 風格的 severity / option / caret
  • -Werror、-Wno-...、-Werror=...
  • #pragma GCC diagnostic push/pop
  • #pragma GCC system_header
  • -Wsystem-headers 與系統標頭抑制
C

巨集與預處理語意

物件巨集、函式巨集、空參數、可變參數巨集、字串化、token pasting，以及 GCC 的逗號消除擴充。

  • # 與 ##
  • __VA_OPT__（C++20）
  • , ## __VA_ARGS__
  • defined / __has_include
  • macro trace 與 include 圖分析 JSON
D

UCN 與 #embed

Universal character name 參與識別字和拼接；#embed 依 GCC 語意嵌入二進位資源。

  • \uXXXX / \UXXXXXXXX
  • 反斜線換行形成的 UCN
  • # / ## 中保留 UCN 拼寫
  • #embed + limit
  • prefix / suffix / if_empty
  • gnu::offset 與 __has_embed
E

PCH 與快取

GCC 13/14/15 都能使用 PCH 策略與快取。快取不是直接解析 GCC PCH，而是驗證、登記、失效並追蹤外部 .gch。

  • --pch=ignore|warn|error|report
  • 強制 include 的 CMake PCH 佈局
  • compiler 路徑、版本、雜湊隔離
  • 原子寫入、目錄鎖、容量和年齡清理
  • 命中率 / stale / corrupt 統計 JSON
F

可重現的測試

三套 GCC、兩個差分語料庫和真實專案共同驗證輸出，不只測試「預處理成功」。

  • GCC15 / 14 / 13 各 65/65 CTest
  • differential corpus 13/13
  • realworld corpus 3/3
  • CrucibleCpp .i → 目標 GCC → exe → run
  • GCC g++.dg/cpp testsuite 迴歸
Positioning

它取代的是預處理步驟，不是編譯器

CrucibleCpp 不做程式碼產生、不做最佳化、不解析 GCC 二進位 PCH。它只負責把原始檔變成確定的 .i，把診斷、相依性和可分析資訊交給建置系統。
