Why CrucibleCpp

A preprocessing layer you can verify

Every positive case follows the same path: CrucibleCpp emits .i, the matching GCC compiles it to an executable, and the executable is run.

01

Explicit target version

Choose with --gcc-version or --gcc. Profile, built-in macros and include paths all come from the same target compiler.

02

GCC-shaped diagnostics

Source carets, include traces, warning IDs, -Werror, pragma diagnostic stacks and system-header suppression.

03

Real-project validation

nlohmann/json, fmt and spdlog are preprocessed, compiled and run with GCC 13, 14 and 15.

04

Complete UCN support

\uXXXX and \UXXXXXXXX in identifiers, #, ##, validation and normalized output.

05

#embed

Binary embedding, limit, gnu::offset, prefix, suffix, if_empty and __has_embed.

06

Version-safe PCH

PCH policy and cache work with GCC 13/14/15. Manifests record compiler path, version and executable hash.

Compatibility

Start with an explicit matrix

The production target is Windows x64 with MinGW-w64 UCRT64. Each GCC version uses its own profile and headers; output is compiled by the matching GCC.

Documentation

From the first command

Quick start

Put the target GCC on PATH, then replace your g++ -E step.

cruciblecpp-preprocessor.exe -P ` -std=c++20 src\main.cpp -o build\main.i g++ -std=c++20 build\main.i -o build\main.exe

Or select the compiler explicitly:

cruciblecpp-preprocessor.exe ` --gcc "D:\path\to\g++.exe" ` -P src\main.cpp -o build\main.i

Target GCC

Never mix a profile with another compiler’s headers.

  • --gcc-version=13|14|15
  • --gcc <g++.exe>
  • PATH auto-detection; highest supported version by default
  • -std=c++11|14|17|20
Auto-detection scans PATH only. Use --gcc for custom installs.

About

A verifiable layer, not another macro expander

CrucibleCpp exists to make translation phases 1–4 observable and testable. It is not a compiler: no code generation, optimization, linking or binary PCH parsing.
