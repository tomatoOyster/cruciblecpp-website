Ta strona obejmuje instalację, wybór docelowego GCC, najczęstsze polecenia, PCH, diagnostykę i rozwiązywanie problemów. Pełna implementacja i matryca testów są dostępne w repozytorium GitHub.

Instalacja

Pobierz archiwum Windows x64 i rozpakuj je do dowolnego katalogu. CrucibleCpp to statycznie linkowany program jednoplikowy, więc nie trzeba instalować środowiska uruchomieniowego.

cruciblecpp-preprocessor.exe --version # cruciblecpp-preprocessor 3.0.1
Bieżący cel produkcyjny: Windows x64 + MinGW-w64 UCRT64. Inne platformy, ABI i wersje GCC nie są objęte gwarancją wsparcia.

Szybki start

Najpierw upewnij się, że w PATH znajduje się docelowy g++.exe. Następnie zastąp dotychczasowe g++ -E:

# Preprocessing .\cruciblecpp-preprocessor.exe -P -std=c++20 src\main.cpp -o build\main.i # Kompilacja tym samym GCC g++ -std=c++20 build\main.i -o build\main.exe

Jeśli docelowy GCC nie znajduje się w PATH, użyj --gcc i wskaż go jawnie:

.\cruciblecpp-preprocessor.exe ` --gcc "D:\GCC1413\gcc14\bin\g++.exe" ` -P -std=c++20 src\main.cpp -o build\main.i

Wybór GCC

CrucibleCpp korzysta z predefiniowanych makr docelowego GCC,__has_* danych i ścieżek wyszukiwania include. Nie używaj profilu GCC15 do preprocessingu nagłówków GCC14.

SposóbZachowanie
--gcc-version=13|14|15Wyszukiwanie w PATH najwyższego obsługiwanego kompilatora zgodnego z wersją główną
--gcc <g++.exe>Użycie wskazanego kompilatora wraz z odczytem jego wersji i ścieżek include
Nie podanoSkanowanie PATH z domyślnym wyborem najwyższej obsługiwanej wersji (15 → 14 → 13)
Automatyczne wykrywanie skanuje tylko PATH. Jeśli kompilator jest zainstalowany w innym katalogu, dodaj go do PATH lub użyj --gcc i nie polegaj na stałej literze dysku.

Obsługiwane profile standardów:

-std=c++11 C++11 profile -std=c++14 C++14 profile -std=c++17 C++17 profile -std=c++20 C++20 profile

PCH

GCC-owe g++ -E nie używa .gch; PCH jest używany tylko podczas rzeczywistej kompilacji. CrucibleCpp domyślnie czyta źródła nagłówków i opcjonalnie weryfikuje, rejestruje oraz buforuje zewnętrznie wygenerowane PCH.

# Ostrzeżenie po napotkaniu .gch --pch=warn # Natychmiastowy błąd po napotkaniu .gch --pch=error # Zapis ignorowanych PCH w analysis JSON --pch=report

Włączanie pamięci podręcznej PCH:

.\cruciblecpp-preprocessor.exe ` --pch-cache .cache\pch ` --pch-cache-stats .cache\pch\stats.json ` -P src\main.cpp -o build\main.i

Manifest pamięci podręcznej zapisuje ścieżkę kompilatora, wersję, hash kompilatora i hash opcji. PCH z GCC13/14/15 nie kolidują ze sobą.

Diagnostyka

Domyślnie wypisywane są wiersze źródłowe i caret w stylu GCC. Można to wyłączyć lub dostosować:

-fdiagnostics-color=auto|always|never -fno-diagnostics-show-caret -fno-diagnostics-show-option -Werror -Wno-error=name --max-errors 20

Obsługuje #pragma GCC diagnostic push/pop/ignored/warning/error i #pragma GCC system_header. Nagłówki z -isystem domyślnie wyciszają zwykłe ostrzeżenia, a-Wsystem-headers może je ponownie wyświetlić.

Rozwiązywanie problemów

Nie znaleziono nagłówków biblioteki standardowej

Docelowego kompilatora nie ma w PATH. Użyj --gcc , aby go wskazać, albo dodaj jego katalog bin do PATH. Możesz też użyć -isystem i przekazać go jawnie.

Wybrano niewłaściwą wersję GCC

Użyj --gcc-version=13|14|15 , aby ustalić wersję główną, lub użyj --gcc , aby wskazać konkretny g++.exe. Nie mieszaj profilu docelowego z nagłówkami innej wersji.

Pamięć podręczna PCH zgłasza corrupt

PCH nie pasuje do bieżącego kompilatora/opcji lub plik jest uszkodzony. Usuń odpowiedni wpis pamięci podręcznej i wygeneruj go ponownie; możesz też całkowicie wyłączyć pamięć podręczną PCH, aby czytała źródła nagłówków.

Nie można skompilować wyniku w GCC

Najpierw upewnij się, że preprocessing i kompilacja używają tej samej wersji GCC i -std. Następnie skompiluj osobno „.i wygenerowany przez CrucibleCpp”, aby sprawdzić, czy problem pochodzi z etapu preprocessingu.

CrucibleCpp to preprocesor, a nie kompilator. Nie odpowiada za generowanie kodu, optymalizację, linkowanie ani parsowanie wewnętrznego formatu binarnego PCH GCC.
